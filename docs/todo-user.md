## 🔴 A. Actions 변수 `APP_URL` 넣기 (2026-10-04, docs/infra.md 25.944)

GitHub 저장소 → Settings → Secrets and variables → Actions → **Variables** 탭 → `New repository variable` → 이름 `APP_URL`, 값은 웹앱 주소(예 `https://….vercel.app`, 끝에 `/` 없이).
넣으면 다음 아침 리포트부터 종목 줄에 "매매 입력" 링크가 붙어 탭 한 번에 매매 폼이 열린다. 안 넣어도 리포트는 전과 같다.

지금은 GitHub cron 이 유일한 경로인데 **이 저장소에서 2~4시간 늦는 것을 실측했다**:

| 워크플로 | 예약 | 실제 | 지연 |

| 국내 뉴스 감성 채점 | 22:40 UTC | 00:45 UTC | +2시간 5분 |

09:05 KST 를 고른 이유가 **"D1 하루 쓰기 한도가 막 풀린 때"** 인데, 4시간 늦으면 그 이유가 사라진다.
CLAUDE.md 에도 "Actions cron 은 지연·누락이 잦아 예비로만 사용" 이라고 적혀 있다.

> **2026-09-22 확인 — 나머지는 다 되고 있습니다.** GitHub API 로 `repository_dispatch` 로
> 시작된 실행을 세어 봤습니다(읽기만 했습니다).
>
> | 무엇을 깨웠나 | 횟수 | 마지막 |
> |---|---:|---|
> | 일일 배치 (국내) | 5 → 7 → 8 | 9/24 23:27 UTC = 9/25 08:27 KST |
> | 일일 배치 (미국) | 4 → 6 → 7 → **8** | 9/25 18:01 UTC |

>
> **2026-09-26 다시 셈.** 국내·미국은 계속 들어오는데(위 화살표) `D1 따라잡기` 는
> 엿새째 0건입니다. 아래 1번을 등록하기 전까지는 계속 0 입니다.
>
> 즉 cron-job.org 는 **살아서 제 시각에 잘 부르고 있습니다.** 등록된 작업만 부를 뿐입니다.
> 이 하나만 더 만들면 됩니다. (지금은 Actions 가 멈춰 있어 불려도 실패로 끝나지만,

**무엇을**: 다른 배치 작업(`daily-kr` 등)과 똑같은 모양으로 하나 더 만든다.

| 항목 | 값 |
|---|---|
| 이름 | `D1 따라잡기` |
| 시각 | 매일 **09:05 KST** |
| 방식 | 다른 배치와 같은 `repository_dispatch` 호출 |

[복귀 점검] ✓ 무엇이 깨웠나 (todo-user 1): cron-job.org 가 깨웠다 — todo-user 1번을 지운다

## 🔴 2. cron-job.org 에서 `/api/cron/health` 와 `/api/cron/news` 호출 기록 보기

**왜**: 이 두 경로가 **DB 에 호출 기록을 한 번도 남기지 않았다**(2026-09-19 확인, infra **25.19**).

- `cron_heartbeats` 의 `health` 행은 마이그레이션이 넣어 둔 씨앗 행 그대로다 (`1970-01-01`, `never`)
- `news` 행은 **아예 없다**
- 반면 `intraday` 행은 최근에 쓰였다 → **웹이 DB 에 쓸 수는 있다.** "DB 가 막혀서" 로는 설명이 안 된다

**무엇이 걸려 있나**: `watchTursoReturn()`(Turso 가 풀렸는지 보는 장치)이 **이 두 경로에만** 있었다.
둘 다 안 돌면 **Turso 자동 복귀 감시가 전혀 안 돌고 있는 것**이다. "풀리면 알아서 돌아간다" 고
믿고 있는 바로 그 장치다.

> **2026-09-21 에 덜 급하게 만들었습니다.** 같은 감시를 `/api/cron/intraday` 에도 얹었습니다 —
> 그 경로는 호출 기록이 실제로 남는 유일한 크론입니다(infra 25.47). 다만 **평일 09:00~15:55 KST
> 에만** 불리므로 완전한 대체는 아닙니다. 아래 확인은 여전히 필요하지만 **급하지는 않습니다.**

**무엇을**: cron-job.org 에서 두 가지를 본다.

1. `/api/cron/health` 와 `/api/cron/news` 작업이 **등록돼 있는가**
2. 있다면 최근 호출 결과가 **401 인가 200 인가**

**결과별로 할 일**:

| 본 것 | 뜻 | 할 일 |
|---|---|---|
| 작업이 없다 | 등록을 안 했다 | 등록한다 — **health 매 60분 · 미국 news 매 1분 · 국내 news-kr 매 60분** (주소와 시각은 docs/intraday.md 4장 표) |
| 401 | 헤더 `x-cron-secret` 값이 Vercel 의 `CRON_SECRET` 과 다르다 | 값을 맞춘다 |
| 200 인데 DB 에 기록이 없다 | 경로 안에서 조용히 실패하고 있다 | 세션에게 알려 준다. 코드를 파야 한다 |

**왜 세션이 못 하나**: `health` 경로는 토큰이 틀리면 호출 기록을 쓰기 **전에** 401 로 되돌아간다.
그래서 "등록 안 됨" 과 "토큰 불일치" 가 DB 에서 똑같아 보인다. 배포된 경로를 직접 찔러 보면
가려낼 수 있는데 **프록시가 `vercel.app` 을 막는다**(infra 25.17). 사용자만 볼 수 있다.

## ⚪ 3. 텔레그램 "📦 D1 따라잡기" 메시지 훑어보기 — 이제 거의 필요 없다

**왜**: 따라잡기가 넣은 실제 숫자(유니버스 종목 수, 받은 거래일 수, 각 단계가 건너뛰었는지)가
Actions 로그 안에 있는데 **클라우드 세션은 그 로그를 읽지 못한다**(프록시가
`*.blob.core.windows.net` 을 막는다, infra 25.17).

**무엇을**: 메시지에 `건너뜁니다` 가 **유니버스·재무·업종** 단계에 붙어 있으면 세션에게 알려 준다
(infra 25.13). 시세 단계의 건너뜀은 정상이다 — 이미 받은 날을 건너뛰는 것이다.

**2026-09-20 부터는 이 항목도 거의 필요 없다.** 따라잡기가 **각 단계의 출력을 그대로**
이슈 #1 "운영 출력 (클라우드 세션용)" 에 올린다(멈춰도 올린다). 세션이 직접 읽는다.
텔레그램은 이제 "잘 돌았나" 를 눈으로 훑는 용도다.

## 🟡 4. 앱을 열어 숫자가 들어왔는지 보기

**왜**: 지금은 **추천이 한 건도 나오지 않는다.** 다섯 팩터 중 계산할 재료가 하나도 없다.
따라잡기가 며칠 돌면서 채워지면 그때 화면에 숫자가 든다.

**언제**: **이제 텔레그램이 날짜로 말해 줍니다** (2026-09-21, infra 25.85).
따라잡기 알림에 이 줄이 생겼습니다.

```
시세가 차기까지 112거래일 · 이 속도면 약 5일 뒤 (따라잡기 한 번에 약 25거래일)
  다만 시세만으로는 안 됩니다 — 재무, 업종도 있어야 합니다
```

둘째 줄이 보이면 시세가 다 차도 아직 추천은 안 나옵니다. 그 줄이 사라지면 곧입니다.
앱에서도 `오늘의 추천` 이 비어 있을 때 **왜 비었는지**를 적어 줍니다(infra 25.86).

> **2026-09-21 정정.** 여기 "세션이 매일 아침 점검해서 알려 준다" 고 적혀 있었다.
> **사실이 아니다** — 세션은 DB 를 직접 못 읽고(프록시), Actions 도 멈춰 있다.
> 사람이 세션을 부르지 않으면 아무도 점검하지 않는다. 그래서 **시스템이 스스로 말하게** 바꿨다.

**무엇을**: `https://<웹앱 주소>` — 표·카드에 숫자가 비어 있으면 어디가
비었는지 말해 준다. 화면 고칠 것이 보이면 말해 준다(고치는 방법은 docs/pwa.md 3.2·3.3).

## 🟡 5. 정해 주셔야 할 것 — DB 가 죽었을 때 로그인 문을 열까 닫을까 (2026-09-20)

지금 로그인 비밀번호는 네 자리입니다. 그래도 되는 이유는 **시도 횟수 제한**이 있어서입니다
(한 주소 15분에 5번, 전체 1시간에 20번). 1만 가지를 다 훑는 데 500시간이 걸립니다.

그 제한은 DB 에 기록을 남겨서 셉니다. 그래서 **DB 를 못 읽으면 셀 수가 없습니다.**
지금 코드는 그럴 때 **문을 엽니다** — 못 세더라도 통과시킵니다.

| 지금 (문을 연다) | 바꾸면 (문을 닫는다) |
|---|---|
| DB 가 안 될 때도 본인은 들어온다 | DB 가 안 되면 본인도 못 들어온다 |
| 그동안 네 자리 비밀번호에 **시도 제한이 없다** | 그동안 아무도 못 뚫는다 |

**지금이 가정이 아닌 이유**: Turso 가 잠겨 있고 D1 은 매일 한도에 닿습니다. DB 가 안 되는
날이 실제로 있습니다. 그때 뚫리면 세션 쿠키가 **30일**짜리라, DB 가 돌아온 뒤에 들어옵니다.

**세션 의견**: 지금(열어 두기)이 무난합니다. 본인이 못 들어오는 쪽이 더 자주 아플 겁니다.
그대로 두시려면 아무것도 안 하셔도 됩니다 — 이 항목은 **알고 있자**는 뜻이지 고치자는 뜻이 아닙니다.
닫는 쪽으로 바꾸고 싶으시면 말씀만 주세요.

## ⚪ 6. 지금은 할 일 없음 — 저절로 되는 것들

기다리면 되는 것. **사람이 손댈 필요 없다.**

- **Turso 복귀**: 풀리면 `turso-return.yml` 이 옮기고 스스로 돌아간다.
  **단 0번이 해결돼야 한다 — Actions 가 멈춰 있으면 복귀도 못 돈다.** 텔레그램에
  "🔓 Turso 가 풀렸습니다" → "✅ Turso 로 돌아왔습니다" 가 온다.
  (2번이 해결되면 감시가 더 촘촘해진다. 지금도 `/api/cron/intraday` 에 같은 감시가
  얹혀 있어 **평일 09:00~15:55 KST 에는 돈다** — infra 25.47)

  복귀가 **온전하지 않으면 ⚠️ 로 온다**(2026-09-21, infra 25.81). 그 경우 종목 이름이 함께 오고,
  **원본은 D1 에 그대로 남아 있다** — 잃은 것이 아니다. 세션에게 그 메시지를 보여 주면 된다
- ~~**데이터 채우기**~~ — **0번이 풀릴 때까지 멈춰 있다.** 아래는 다시 돌기 시작한 뒤의 이야기다.
  9/20 기준 거래일 **163일**, 목표는 200일.

  **며칠 걸리는지는 이제 묻지 않아도 된다** (2026-09-21, infra 25.85). 따라잡기가 최근 실행의
  적재량을 **재서** 텔레그램에 날짜로 적는다. 못 재는 날은 `(속도를 재지 못해 언제일지 모릅니다)`
  라고 말한다 — **어림으로 채우지 않는다.**

  전에 여기 "1~2일" 이라고 적었던 것은 시세가 예산을 독차지할 때의 숫자였고, 9/21 부터는
  재무가 먼저 돌아 시세 몫이 줄어든다. 그래서 **박아 두지 않고 매일 재기로** 했다
