# 종목 찾기 (스크리너)

`/screener`. 추천(`/recommend`)과 짝이다 — **추천은 규칙이 고르고, 여기는 내가 조건을 정한다.**
조회 SQL 은 `web/lib/screener.ts buildQuery`, 실제 스키마에 돌리는 테스트는 `web/__tests__/screenerSql.test.ts`.

## 1. 원칙

- 웹은 **새 수치를 만들지 않는다.** PER·PBR·ROE·부채비율·영업이익률·성장률은 배치 값(`factors.raw_json`)을 읽고 단위만 바꾼다
  (역수·× 100, 6장 표. docs/infra.md 25.490). 그 나라의 가장 최근 `factors.as_of_date`·가장 새 `calc_version` 을 쓰고, 그 기준일을
  `factors_asof` 로 함께 보여 준다. 대체식(25.239)·연결/별도 선택(25.314)은 배치가 이미 적용한 값이다
- 국내·미국은 탭으로 나눈다. 단위(억원 / $M)와 조건이 달라 섞으면 뜻이 바뀐다
- 미국도 재무 조건·열·정렬이 있다(25.249 에 재무 수집이 붙었다. 25.365 에서 열과 정렬도 맞췄다)

## 2. 저장한 조건 (Step 23, 2026-09-17)

설계서 3.5 의 `screener_presets`(마이그레이션 0033). 고정 프리셋(저평가 우량·성장·대형 안정)은 코드에 있고,
**내가 만든 조건**은 이름을 붙여 저장한다. 나라별로 따로이고 같은 이름은 덮어쓴다. 누르면 조건을 되살려 조회하고
`last_used_at` 을 적는다. 조건은 JSON 그대로 둬서 항목이 늘어도 표를 바꾸지 않고, 읽을 때 스키마로 다시 검사해
모자란 항목은 기본값으로 메운다(`parsePreset`). 깨졌으면 그 사실을 보여 준다.

## 3. CSV 내보내기 (Step 23)

결과 표의 값을 그대로 파일로. 브라우저 안에서 만들고 서버를 거치지 않는다. BOM 을 붙여 엑셀에서 한글이 깨지지
않게 한다. 열은 `CSV_COLUMNS` — 화면에 기본으로 안 보이는 열(샤프·변동성, 국내 거래대금)도 넣는다(화면은 걸거나 정렬한 값의 열만 더한다, 25.777). 성과 열 이름에는 기간을, 따로 성과 지표 기준일 열을 둔다(25.779). **데이터 이용 조건**: 시세 자료는
개인 참고용이고 외부 제공이 금지돼 있다(CLAUDE.md). 파일도 같다.


## 4. 업종·감성 조건 (Step 33, 2026-09-17)

설계서 4번 화면이 요구하는 필터 중 빠져 있던 둘이다.

- **업종**: `stocks.sector` 의 값을 그대로 고른다. 목록은 API 가 그 나라 DISTINCT 로 만들어 준다 — 화면이 업종 표를 들고 있지 않아 배치가 분류를 바꾸면 화면도 따라간다. 업종이 비어 있는 종목은 "전체" 에서만 보인다
- **감성**: `sentiment_scores` 의 **가장 최근 기준일** 값. 단 **팩터 기준일에서 3일 넘은 값은 쓰지 않는다**(배치 `sentiment.MAX_AGE_DAYS` 와 같다, 2026-09-28 infra 25.577 — 수집 대상에서 빠진 종목의 몇 달 전 값이 조건·정렬에 올랐다). 수집 대상 상위 종목(설정 `sentiment_target_top_n`)에만 있어, 범위를 걸면 값이 없는 종목은 빠진다. 센티먼트는 5팩터와 별도 축이므로(CLAUDE.md) 화면에서도 따로 묶고 결과 표에 열로 보인다

**MDD 조건은 낙폭의 크기(양수 %)로 받는다** — 30 이하면 "30% 넘게 빠진 적 없음"(2026-09-30, docs/infra.md 25.770). 결과 열·CSV 의 MDD 값은 예전처럼 음수로 보인다. CSV 에도 감성과 기준일이 들어간다. 정렬 기준에도 감성을 넣었다. CSV 의 CAGR·MDD·변동성은 열 이름대로 **%** 다(화면과 같다, 25.577 — 비율 그대로 나가 100배 작았다). 정렬은 같은 값이면 종목 번호 순이다.

## 5. 0건일 때 (2026-09-23, docs/infra.md 25.149)

**"범위를 넓혀 보세요" 는 늘 맞는 말이 아니다.** `WHERE per <= 10` 은 `per` 이 `NULL` 인
종목을 **전부 버린다** — SQL 에서 `NULL <= 10` 은 거짓이 아니라 `NULL` 이고, `WHERE` 는
참이 아닌 행을 버린다. 재무가 아직 안 채워졌으면 범위를 아무리 넓혀도 0건이다.

그래서 한 건도 없을 때 **값 조건을 전부 뺀 같은 조회를 한 번 더** 하고 셋을 가른다
(`whyEmpty`, 25.86 이 추천 화면에서 가른 것과 같은 셋).

| 본 것 | 뜻 | 화면이 하는 말 |
|---|---|---|
| 조건을 다 빼도 0건 | 종목 마스터·유니버스가 비었다 | 조건 탓이 아니라고 말하고 [시스템 상태]로 보낸다 |
| 종목은 있는데 **건 조건의 값이 모두 빈칸** | 그 자료가 아직 없다 | **"범위를 넓혀도 나오지 않습니다"** — 무엇이 비었는지 이름을 댄다 |
| 값도 있다 | 정말로 조건이 좁다 | 그때만 "범위를 넓혀 보세요" |

질의가 하나 느는 것은 **0건인 화면에서만**이다. 값 조건 목록은 `VALUE_FILTERS` 가
정의처이고, 그 표의 `field` 가 결과 칸 이름과 맞는지는 테스트가 지킨다 — 이름이 틀리면
`undefined === null` 이 거짓이라 **언제나 "값이 있다"** 로 읽혀 이 장치가 통째로 죽는다.

## 6. 비율을 배치 값으로 옮기는 설계 (2026-09-28, docs/infra.md 25.488)

1장에 있던 "알고 둔 예외"(웹 SQL 이 PER·PBR·ROE 를 나눈다)를 없애는 설계다. 웹 감사(25.483)가 짚은 것은 두 가지다.
- **규칙 위반** — CLAUDE.md "웹앱은 계산하지 않는다".
- **식이 배치와 다르다** — 스크리너 PER 은 "주간 유니버스 스냅샷 시총 ÷ 가장 최근 사업연도 순이익" 이다. 배치 E/P 는 "점수 기준일 시총 ÷
  그날까지 공시된 재무(`pit_financials`)" 다. 같은 종목에서 스크리너 PER 과 상세 화면 E/P 의 역수가 달라진다.

**마이그레이션은 필요 없다 — 1장의 "표가 없다" 는 틀렸다.** 배치는 이미 날마다 `factors.raw_json` 에 그 값을 남긴다.

| 스크리너 열 | 배치 값 (`factors.raw_json`) | 화면 변환(서식만) |
|---|---|---|
| PER | value.`ep` | 1 / ep (ep ≤ 0 이면 비움 — 적자 PER 은 뜻이 없다) |
| PBR | value.`bp` | 1 / bp |
| ROE | quality.`roe` | × 100 (%) |
| 부채비율 | quality.`debt_ratio` | × 100 (%) — 대체식(25.239)은 배치가 이미 적용 |
| 영업이익률 | quality.`operating_margin` | × 100 (%) |
| 매출·영업이익 성장률 | growth.`revenue_growth`·`operating_income_growth` | × 100 (%) |

- 역수·× 100 은 **단위 바꾸기**라 "계산" 이 아니다(점수·신호를 만들지 않는다). 기준일은 `factors.as_of_date` 로 보여 준다
- 읽는 행: 그 나라의 가장 최근 `factors.as_of_date`·가장 새 `calc_version` 의 value·quality·growth 세 줄(`json_extract`).
  유니버스 편입 종목만 점수가 있다. **"유니버스만" 을 끄면(미국 탭 기본) 유니버스 밖 종목은 비율이 빈다** — 25.490 전에는 웹이 나눠 값이
  있었다(퇴행, 25.491 교차검증). 기준 줄이 "비율 없는 N종목" 으로 수를 말한다. 비율 조건을 걸면 그 종목들은 조건을 통과하지 못해 빠진다(아래)
- 기준일 찾기는 `ORDER BY … DESC LIMIT 1` 로 쓴다(25.491). 통계(ANALYZE)가 있는 SQLite 에서 `MAX()` 는 모든 날짜를 읽는 계획을
  골랐다. 통계가 없으면 둘 다 싸다. 다른 나라 행이 더 최근이면 그만큼 지나쳐 읽는다. D1·libsql 의 계획은 `[확인필요]` (25.497)
- **"유니버스만" 을 끄고 비율 조건(PER·PBR·ROE·부채비율·영업이익률·매출/영업이익 성장률, 25.500)을 걸면** 값이 빈 종목이 조건에서 빠진다. 결과 안내에
  그렇다고 한 줄 적는다(`ratioFilterNote`, 25.497). 빠진 수는 세지 않는다 — 조회가 한 번 더 든다
- 달라지는 것: 팩터를 못 낸 종목(절반 규칙으로 점수가 빈 종목 포함)은 그 열이 빈다. 대신 값은 화면·점수·신호와 **같은 숫자**가 된다
- 단계
  1. 조회 SQL 에 배치 값 열을 **나란히** 추가하고, 테스트로 두 값이 같은 입력에서 어떻게 다른지 적는다 — **했다(25.490)**.
     나란히 두는 기간 없이 바로 바꿨다. 기준일·판은 나라 기준 비상관 하위질의(CTE `factors_asof`·`factors_ver`, 25.428)로 잡는다
  2. 조건·정렬·CSV 를 배치 값으로 바꾼다. 웹 나눗셈을 지운다. 1장의 예외 문장을 지운다 — **했다(25.490)**. CSV 에 "비율 기준일" 열을 더했다
  3. `sum`·`ratio` 같은 계산이 웹 SQL 에 다시 생기지 않게 검사를 둔다
