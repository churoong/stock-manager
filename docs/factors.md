## 2. 정규화 규칙

모든 팩터가 같은 절차를 쓴다. 절차가 팩터마다 다르면 점수를 비교할 수 없다.

### 2.1 비교 집단(peer group)

```
1순위  sector:<시장>:<업종>     업종 데이터가 채워진 뒤
2순위  market:<시장>            KOSPI / KOSDAQ / NASDAQ / NYSE
```

- **시장이 다르면 절대 같은 집단에 넣지 않는다.** 한국과 미국을 한 잣대로
  비교하지 않는다는 `CLAUDE.md` 규칙이 여기서 강제된다
- 집단의 **종목 수가 30 미만이면 한 단계 위로 올린다.** 표본 12개로 낸
  z-score 는 순위가 아니라 잡음이다. 지표별 유효 표본이 아니라 집단의 종목
  수로 판정한다. 지표마다 집단이 달라지면 점수를 서로 비교할 수 없다
- 어느 집단으로 계산했는지 `factors.peer_group` 에 반드시 남긴다
- **시장 집단의 비교 대상은 그 시장의 모든 종목이다** (2026-09-27, docs/infra.md 25.307). 작은 업종에서 올라온 종목끼리만 묶지 않는다 —
  z 는 시장 전체(자기 업종 집단이 있는 종목 포함)로 내고, 점수는 올라온 종목에만 적는다. `peer_size` 는 시장 전체 수, 집단 내 순위는 시장 순위다

### 2.2 z-score 와 0~100 변환

```
1. 같은 집단에서 그 지표의 값을 모은다 (NULL 제외)
2. 윈저라이즈: 상·하위 1% 를 그 분위값으로 자른다. **적어도 한 종목씩** (값이 **10개 미만**이면 안 자른다 — 25.309)
3. z = (x - 평균) / 표준편차
4. 표준편차가 0이면 z = 0          (모두 같은 값이면 우열이 없다)
5. 방향이 반대인 지표는 z 에 -1 을 곱한다
6. 팩터 z = 구성 지표 z 의 평균   (NULL 인 지표는 평균에서 제외)
7. 점수 = clamp(50 + 50 × z / 3, 0, 100)
```

- **2번 윈저라이즈가 없으면 한 종목이 집단 전체를 망친다.** PER 역수 같은
  비율 지표는 분모가 0에 가까워지면 값이 폭발한다
- **"적어도 한 종목" 인 이유** (2026-09-26, docs/infra.md 25.245, 계산 판 5): 1% 는 100 종목 이하 집단에서 자르는 자리가
  최솟값·최댓값 자신이라 아무것도 안 잘렸다. 업종 집단은 30 종목부터 쓰므로(2.1) 대부분의 집단에서 2번이 없던 셈이다
- **7번의 ±3σ 절단**은 z = +3 을 100점, z = -3 을 0점으로 본다는 뜻이다.
  정규분포라면 상위 0.13% 가 만점이다. 만점이 흔하면 이 계수를 다시 본다
  - **단, 이 "0.13%" 는 7번에 들어가는 z 의 분산이 1 일 때만 맞다** (2026-10-01 정정, 6회차 3 검증 2, docs/infra.md 25.855).
    7번의 z 는 6번에서 **지표 z 를 평균한 값**이라, 지표 k 개의 평균 상관이 ρ 면 표준편차가 √((1+(k−1)ρ)/k) 로 줄어든다
    (지표 3개·ρ=0.3 이면 약 0.71). 그래서 실제로는 만점·0점이 0.13% 보다 훨씬 드물고 점수가 50 근처로 몰린다 — 팩터마다 지표 수가 달라
    **팩터 사이 점수 폭도 다르다.** 순위(팩터 안)는 바뀌지 않는다. 다시 표준화할지는 6회차 3(꺼진 채 A/B 대기)이 정한다
- 반올림은 **소수 첫째 자리까지.** 정수로 자르면 순위 동점이 과하게 생긴다

## 3. 팩터 다섯 개

표의 "방향"은 값이 클 때 좋은지(+) 나쁜지(−)다. −인 지표는 2.2의 5번에서
부호를 뒤집는다.

### 3.1 밸류 (value) — 싼가

| 지표 | 계산식 | 입력 | 방향 |
|---|---|---|---|
| 이익수익률 E/P | `net_income / market_cap` | financials, universe_members | + |
| 순자산수익률 B/P | `total_equity / market_cap` | 〃 | + |
| 매출수익률 S/P | `revenue / market_cap` | 〃 | + |
| 배당수익률 D/P (2026-09-21) | `cash_dividend_total / market_cap` | stock_dividends, universe_members | + (11.1 절) |

**PER 이 아니라 그 역수를 쓴다.** PER 은 적자 기업에서 음수가 되어 "가장
싼 종목"으로 올라오고, 이익이 0에 가까우면 무한대로 발산한다. 역수는
적자를 자연스럽게 음수(나쁨)로 두고 0 근처에서 연속이다.

- `market_cap` 이 NULL 이면 세 지표 모두 NULL
- 분모가 0 이하이면 그 지표는 NULL (0으로 나누지 않는다)
- **EV/EBITDA 는 넣지 않는다.** 현금·차입금 컬럼이 `financials` 에 없다.
  없는 숫자를 만들지 않는다
- **배당수익률은 2026-09-21 에 더했다.** `financials` 가 아니라 **`stock_dividends`**
  표에서 온다 — 그 표는 진작부터 양국을 모으고 있었는데 점수가 한 번도 안 봤다(11.1 절).
  2026-09-20 까지 이 자리에는 "배당 컬럼이 `financials` 에 없다" 고만 적혀 있었다.
  **찾은 곳이 없다는 말이지 자료가 없다는 말이 아니었다**
- 배당수익률은 **모르는 것과 0 을 가른다.** 무배당은 0 으로 들어오고, 수집이 안 닿은
  종목은 아예 값이 없다(NULL). 그 둘을 같게 보면 "배당 안 주는 회사" 와 "아직 안 받아
  온 회사" 가 한 값이 된다
- 시점 규칙: `stock_dividends.as_of_date`(접수일) **이하**만 본다. 접수일이 NULL 인
  행은 아예 쓰지 않는다 (`docs/infra.md` 25.92)

**분모 시점 규칙** (2026-10-05, 13회차, calc_version 9 → 10, `docs/infra.md` 25.954·25.960). `market_cap` 은 **주 1회** 유니버스 스냅샷의 값이라
매 거래일 도는 점수에서 밸류 넷의 분모만 며칠 전 가격이었다(모멘텀·리스크·신호는 기준일 종가). 스냅샷 시총을 기준일 가격으로 옮긴다:

```
분모(c) = 스냅샷 시총 × 배수
배수    = 국내: Π_{d ∈ (시총 날짜, c]} (1 + prices.change_pct(d)/100)   ← KRX 등락률은 기준가 조정 뒤 값이라 분할·권리락을 건넌다
          미국: 수정종가(c) / 수정종가(시총 날짜)                        ← 일일 적재가 10 달력일 창 안을 같은 기준으로 덮는다
옮기는 조건 = 시총의 가격 날짜(stocks.market_cap_date) ≤ 스냅샷 날짜  AND  둘의 차이 ≤ 14일  AND  배수를 낼 수 있다  AND  0.5 ≤ 배수 ≤ 2.0
              미국은 추가로: 시총 날짜가 기준일에서 10일 안  AND  수정주가 재수집 대기(adjust_refresh_queue.done_at IS NULL)가 아님
아니면      = 스냅샷 시총 **그대로**(전과 같다) + raw_json._market_cap.scaled=false 와 사유
```

- 왜 이 날짜 조건인가: 시총이 **어느 날 가격의 값인지는 `market_cap_date` 가 말한다** — 거기서부터 옮긴다(13회차 검증 B 의 조건). 시총 날짜가 스냅샷보다
  **늦으면** 스냅샷 뒤에 덮어쓴 값이거나 `--as-of` 로 옛 스냅샷을 다시 세는 것이라 이 스냅샷의 시총이 아니다 — 옮기지 않는다. **14일 넘게 앞서면**
  KRX 빈 응답·한도로 지난 시총을 복사한 것이라(`refresh_kr_market_cap`) 옮기지 않는다(유니버스의 묵은 시총 경고와 같은 14일)
- 처음(25.954)에는 "시총 날짜 == 스냅샷 날짜" 로 더 엄격히 했다. 그런데 **미국은 구조적으로 하루 어긋난다** — 토요일 `us_shares` 가 그때 마지막 종가(목요일,
  금요일 종가는 월요일 아침 배치가 받는다)로 시총을 내고 일요일 스냅샷 날짜는 금요일이다. 10-05 실측 1,860종목 전부가 걸려 한 번도 옮기지 못해 25.960 에서 고쳤다
- 왜 등락률 곱인가(국내): 국내 일일 적재는 `adj_close` 를 비워 두고 `adjust_kr` 은 수동이라, 분할 주에 수정종가 비율을 쓰면 시총이 1/10 이 된다.
  등락률은 분할·권리락을 이미 건넌 값이다. 구간에 등락률이 빈 날이 하나라도 있으면 옮기지 않는다
- 미국 배당락이 낀 주는 수정종가가 배당만큼 낮아 분기 배당률(≈0.5%) 안쪽 오차가 든다 — 허용하고 적어 둔다
- **가격 시점만 맞춘 것이다.** 주식수는 여전히 스냅샷 값(국내 KRX MKTCAP 의 그날 주식수, 미국 `us_shares` 의 주식수)이고, 백테스트는 "오늘
  주식수 × 그날 원 종가" 라 주식수 정의가 다르다. 5회차 A(시점 주식수 이력) 표가 생기면 같은 자리에서 "그날 주식수 × 그날 원 종가" 로 **교체**한다
- 유니버스 편입 판정(주간 스냅샷 시총 하한)은 바꾸지 않는다. `scoring.sue` 의 "시총 하나뿐이면 약분" 은 종목·기준일당 시총이 하나라 그대로다
- 기록: 밸류 팩터 `raw_json._market_cap` = {cap, cap_date, snapshot_date, factor, scaled, reason, source}. 종목 상세 근거표 "시가총액(분모)" 행이 보인다.
  실행 기록 `step_log.market_cap_scaled` 에 옮긴 수와 못 옮긴 사유 분포
- 진단(결과 보기 전에 관문 고정 — |배수−1|>1% 종목이 1% 미만이면 기록만): `scripts/diag/round13_market_cap_move.sql`. 2026-10-05 국내 실측 874종목 가운데
  >1% 781 · >5% 495 · >10% 303 — 다만 그 시총 날짜가 전부 09-16(KRX 빈 응답으로 지난 시총 복사, 스냅샷 10-02 와 16일)이라 **국내는 14일 조건에 걸려 옮기지 않는다**.
  국내가 옮기기 시작하는 것은 KRX 시총 갱신이 다시 되는 주부터다. 미국은 25.960 부터 옮긴다

### 3.2 퀄리티 (quality) — 좋은 회사인가

| 지표 | 계산식 | 입력 | 방향 |
|---|---|---|---|
| ROE | `net_income / total_equity` | financials | + |
| ROA | `net_income / total_assets` | 〃 | + |
| 영업이익률 | `operating_income / revenue` | 〃 | + |
| 부채비율 | `total_liabilities / total_equity`. 부채총계가 비면 `total_assets − total_equity` (DART 가 한쪽만 줄 때가 있다. 스크리너도 같은 식 — docs/infra.md 25.239) | 〃 | − |
| 이익 안정성 | 최근 5개 사업연도 중 영업흑자 연수 ÷ 관측 연수 | 〃 | + |
| 자산 성장률 (2026-09-17) | `total_assets / 전년 total_assets - 1` | 〃 | **−** (10.2 절) |
| 유동비율 (2026-09-17) | `current_assets / current_liabilities` | 〃 | + (10.2 절) |
| 피오트로스키 축소판 (2026-09-17) | 아래 6개 조건 중 참인 개수, 0~6 | 〃 (당해·전년) | + (10.2 절) |

- `total_equity` 가 0 이하(자본잠식)면 ROE 와 부채비율은 NULL.
  자본잠식은 "비율이 나쁘다"가 아니라 **비율이 성립하지 않는 상태**다.
  이 사실은 별도 플래그로 화면에 드러내고, 점수로 뭉개지 않는다
- 이익 안정성은 관측 연수가 **3년 미만이면 NULL**

### 3.3 성장 (growth) — 커지고 있는가

| 지표 | 계산식 | 입력 | 방향 |
|---|---|---|---|
| 매출 성장률 | `revenue / 전년 revenue - 1` | financials | + |
| 영업이익 성장률 | `operating_income / 전년 operating_income - 1` | 〃 | + |
| 매출 3년 CAGR | `(당해 revenue / 3년 전 revenue)^(1/3) - 1` | 〃 | + |

- **전년 값이 0 이하이면 그 성장률은 NULL.** 적자에서 적자 축소는 성장률로
  표현되지 않는다. −100억에서 −10억은 "90% 성장"이 아니다
- 3년 CAGR 은 4개 사업연도가 모두 있어야 한다. 하나라도 비면 NULL

### 3.4 모멘텀 (momentum) — 오르고 있는가

| 지표 | 계산식 | 입력 | 방향 |

| 12-1개월 수익률 | 252 거래일 전 대비 수익률, **최근 21 거래일 제외** | prices | + |

- **최근 한 달을 빼는 이유**는 단기 반전 효과다. 직전 한 달 급등은 다음 달

- **알고 받아들인 근사 하나.** 과거에 거래정지가 있어 창 안에 구멍이 난 종목은

  모멘텀 셋이 통째로 NULL 이 되어 **절반 규칙의 문턱에 정확히 걸린다** — 앞을 골랐다.

  (2026-09-28, infra 25.556 — 전에는 274일만 읽어 정지일 하루에도 셋이 NULL 이었다). 30거래일보다 긴 정지는 NULL
- 가격은 전부 **수정주가**(`COALESCE(adj_close, close)`)를 쓴다. 미국은 야후
  Adj Close, 국내는 거래소 등락률로 되살린 값이다(`docs/adjust.md`). 조정값이
  없는 구간은 원자료로 떨어지므로 그동안은 분할이 가짜 하락으로 잡힐 수 있다

### 3.5 리스크 (risk) — 안정적인가

**이 팩터는 "안정성 점수"다. 값이 100 에 가까울수록 안정적이다.**
2026-09-16 결정(0장). 다른 네 팩터와 방향이 같아야 가중합이 뜻을 가진다.

앞의 일곱은 `performance_metrics` 에서 읽는다 — 그 계산식은 `docs/metrics.md` 가
단일 정의처다. 뒤의 셋(`amihud_illiquidity`·`max_daily_return`·`idio_volatility`)은
**가격 계열에서 그 자리에서 낸다.** 성과지표 표에 없는 값이라 그렇다.

| 지표 이름 | 계산 | 방향 | 비고 |
|---|---|---|---|
| `mdd_abs` | `abs(mdd)` | − | 저장된 MDD 는 음수다. 부호를 그대로 두면 순위가 뒤집힌다 |
| `volatility_ann` | 그대로 | − | |
| `sharpe` | 그대로 | + | 위험 대비 수익 |
| `sortino` | 그대로 | + | 하방 위험 대비 수익 |
| `beta_abs` | `abs(beta)` | − | 1.0 기준이 아니라 **크기**가 작을수록 안정으로 본다 |
| `mdd_recovery_days` | 그대로 | − | 미회복(NULL)은 아래 규칙 참조 |
| `cagr` | 그대로 | + | 창을 여러 개 넣지 않고 **하나의 창**만 쓴다 |
| `amihud_illiquidity` | 최근 63 거래일의 `mean(|일간 수익률| / (거래대금 / 10억))` | − | 2026-09-17 추가. 가격에서 그 자리에서 낸다(성과지표 표가 아니다). 10장 |
| `max_daily_return` | 최근 21 거래일의 **최대 일간 수익률** | − | 2026-09-21 추가. 가격에서 그 자리에서 낸다. 11.2 절 |
| `idio_volatility` | 시장 회귀 잔차의 연환산 표준편차 | − | 2026-09-21 추가. **지수 계열이 더 필요하다** — 베타와 같은 지수를 본다. 11.3 절 |

**절댓값으로 바꾸는 이유**를 분명히 해 둔다. MDD 는 음수로 저장되고 베타도
음수일 수 있다. 부호를 그대로 z-score 에 넣으면 "많이 떨어진 종목"과
"시장과 반대로 움직이는 종목"의 순위가 뒤집힌다. 안정성 축이 보는 것은
방향이 아니라 크기다.

- 창(window)은 **3Y 를 기본**으로 하고, **3Y 를 쓸 수 없으면 1Y 로 내려간다.**
  "쓸 수 없다" 는 **행이 없거나 값이 비어 있는 것**을 함께 뜻한다 —
  `jobs/metrics.py` 는 표본이 모자라도 행을 쓰고 값만 NULL 로 둔다.
  2026-09-21 까지 코드가 창 이름만 보아 **빈 3Y 가 값이 든 1Y 를 이겼다**(`docs/infra.md` 25.97).
  고르는 규칙은 `services/metrics.pick_window()` 한 곳에 있다.
  어느 창을 썼는지 `factors.raw_json` 의 `_metrics_source`({window, as_of_date})에 남긴다
  (2026-09-27, docs/infra.md 25.383 — 그전에는 적어 두고 남기지 않았다)
- **Amihud 의 거래대금**은 저장된 `prices.value` 를 먼저 쓰고, 없으면 원 종가 × 거래량이다.
  국내는 거래소가 준 실측이고 미국은 `prices.value` 에 이미 종가×거래량 추정치가 들어 있다.
  **수정주가로 환산하지 않는다** — "그날 얼마가 오갔나" 라서 조정하면 뜻이 달라진다.
  적재와 백테스트가 같은 규칙을 쓴다(`docs/infra.md` 25.99)
- **MDD 회복 기간의 NULL 은 두 가지 뜻**이다. 회복해서 0일인 것과 아직
  회복하지 못한 것은 정반대다. `performance_metrics` 는 미회복을 NULL 로
  두므로, 팩터에서는 **미회복을 그만큼도 안 빠졌던(MDD 가 같거나 얕은) 종목들의 회복 기간 최댓값으로 치환**한다.
  그런 종목이 없으면 그보다 깊은 종목 가운데 가장 얕은 것의 값, MDD 를 모르면 집단 최댓값이다.
  **어느 경우든 바닥 뒤 지난 행 수보다 짧게 채우지 않는다** — 회복 기간은 적어도 그만큼이다 (calc_version 8, infra 25.691.
  적재는 `prices` 전체에서 바닥 다음 날부터 점수 기준일까지(25.693), 백테스트는 그 시점 계열로 센다)
  (2026-09-29, calc_version 7, docs/infra.md 25.685 — 예전에는 깊이를 보지 않고 집단 최댓값을 넣어, 신고가 다음 날
  −0.75% 인 종목이 −40% 종목과 같은 최악 회복 점수를 받았다). 이 치환 사실을 `raw_json` 에 기록한다. **단, MDD(`mdd_abs`)도 모르면(성과지표 행이 없음)
  미회복이 아니라 모름이다 — 치환하지 않고 결측으로 둔다** (2026-09-28, infra 25.558. 전에는 모르는 종목까지
  최댓값으로 채워 표본에 가짜 최악값이 여러 번 들어가 다른 종목들의 z 가 일괄 이동·압축됐다)
- CAGR 을 안정성 축에 넣는 것은 `CLAUDE.md` 의 리스크 팩터 정의를 따른
  것이다. 수익성 지표가 섞여 있다는 점은 알고 쓴다

## 4. 결측 규칙

**묵은 사업보고서는 결측이다** (2026-09-30, docs/infra.md 25.804). 가장 새 사업보고서의 접수일이 기준일보다 457일(`scoring.STALE_ANNUAL_DAYS` — 결산 뒤 약 3개월 제출 + 12개월 주기 + 여유)
넘게 앞서거나, **7월 이후인데 최신 회계연도가 재작년 이전이면**(정정공시가 접수일을 새로 덮는 경우, 25.663·25.808) 그 종목의 연간 재무를 쓰지 않는다 —
밸류(E/P·B/P·S/P)·퀄리티·성장의 재무 지표가 결측이 되어 아래 규칙대로 간다. 운영 점수·백테스트·신호 중기 성장률(25.660)이 같은 함수(`scoring.annual_stale_reason`)를 쓴다.
실행 기록 `step_log.stale_annual` 에 종목과 사유가 남는다.

값을 만들어 내지 않는다는 규칙을 단계마다 적용한다.

| 단계 | 규칙 |
|---|---|
| 지표 | 입력이 NULL 이거나 분모가 성립하지 않으면 NULL |
| 팩터 | 구성 지표의 **절반 미만**만 살아 있으면 팩터 NULL (3개 중 1개 → NULL, 3개 중 2개 → 계산). 지금의 문턱은 아래 표 |
| 종합 점수 | 5팩터 중 **2개 이상 NULL 이면 종합 점수를 내지 않는다.** 랭킹에서 빠지고 사유를 남긴다. **가중치 0 인 팩터의 결측도 센다**(글자 그대로의 규칙 — {50,50,0,0,0} 이면 쓰지도 않는 두 팩터가 비어 빠질 수 있다. 의도인지 `[확인필요]`, 25.768) |
| 종합 점수 | 1개만 NULL 이면 나머지 4개의 가중치를 합이 100이 되도록 재정규화 |
| 센티먼트 | 가중치가 0이거나 값이 없으면 **5팩터를 재정규화**한다 (`CLAUDE.md` 규칙) |

**팩터별 지표 수와 문턱** (2026-09-21, `CALC_VERSION` 4 기준).
`batch/services/scoring.FACTOR_METRICS` 가 단일 정의처이고
`tests/test_scoring_new_metrics.py` 가 이 표와 대조한다.

| 팩터 | 지표 수 | 최소 살아 있어야 할 개수 | 언제 바뀌었나 |
|---|---|---|---|
| 밸류 | **4** | 2 | 3 → 4 (배당수익률, 11.1) |
| 퀄리티 | 8 | 4 | 2026-09-17 에 5 → 8 (10.2) |
| 성장 | 3 | 2 | 그대로 |
| 모멘텀 | 6 | 3 | 2026-09-17 에 3 → 6 (10.1) |
| 리스크 | **10** | **5** | 8 → 10 (MAX·잔차 변동성, 11.2·11.3) |

> **지표를 더하면 문턱이 오른다.** 밸류는 3→4 에서 문턱이 2 그대로지만, 리스크는
> 8→10 에서 4→5 로 올랐다. 리스크 지표를 4개만 가진 종목은 **이번 변경으로 점수를
> 잃는다.** 알고 한 일이다 — 자세한 것은 11.0 절.
>
> 그러므로 **값을 만들지 못하는 지표를 등록하면 안 된다.** 분모만 키워 멀쩡한 종목의
> 점수를 지운다. `tests/test_every_metric_is_produced.py` 가 등록된 지표를 적재 경로와
> 백테스트 경로가 **둘 다** 만드는지 본다 (`docs/infra.md` 25.92).

빠진 지표는 `factors.missing_fields` 에 이름으로 남긴다. "왜 이 종목이
점수가 없나"를 나중에 물을 수 있어야 한다.

## 5. 종합 점수

```
정규화가중치 = 살아 있는 팩터들의 가중치를 합이 100이 되도록 다시 나눔
팩터합      = Σ(팩터점수 × 정규화가중치) / 100          → 0~100
종합점수    = 팩터합 + (센티먼트점수를 0~100 으로 옮긴 값 − 50) × (센티먼트가중치/100),  0~100 으로 자름
```

- **중립 감성은 점수를 움직이지 않는다** (2026-09-29, calc_version 6, docs/infra.md 25.639). 예전 식
  `팩터합 × (1−w) + 센티먼트 × w` 는 팩터합을 센티먼트 쪽으로 당겨, 팩터합이 50 보다 높은 종목은 중립 감성에도 깎였다.
  감성이 없는 종목은 재정규화로 팩터합 그대로라(248줄) **기사가 있는 상위 종목만 손해**였다. 가중치 10% 면 감성이 점수를
  최대 ±5점 움직인다

- 센티먼트는 −100~+100 이므로 `(센티먼트 + 100) / 2` 로 0~100 에 옮긴다
- **화면에는 항상 분리 표시한다.** 종합 점수 옆에 센티먼트를 따로 보여 주고,
  섞인 값 하나만 보여 주지 않는다 (`CLAUDE.md`)
- 가중치는 계산 시점의 값을 `scores.weights_json` 에 **스냅샷으로 저장**한다.
  나중에 가중치를 바꿔도 과거 점수를 그대로 재현할 수 있어야 한다
- 가중치를 바꿔도 **이미 계산한 날의 행은 그대로다** — 일일 배치는 그날만 계산하고, 각 행은 `weights_json` 에
  그때의 가중치를 담는다. 다만 **지난 날을 `--as-of` 로 다시 돌리면** 그날 행은 지금 가중치로 바뀐다(같은 판을
  지우고 넣는다). `calc_version` 은 **계산식**이 바뀔 때 올리는 것이지 가중치 때 올리지 않는다
  (2026-09-27 바로잡음, docs/infra.md 25.383 — 전에는 "가중치를 바꾸면 calc_version 을 올려 쌓는다" 고 사실과 다르게 적었다)
- **가중치가 0~100 밖이면 점수를 내지 않는다** (2026-09-23, docs/infra.md 25.169).
  예전 식(25.639 전)은 범위 밖 값에서 0~100 약속이 깨졌다 —
  `센티먼트가중치 = 150` 이면 종합 점수가 **−40** 이 나왔다(지금 식은 잘라서 0~100 을 지키지만 ±75점을 움직이는 가중치는
  여전히 뜻이 없다). 음수 팩터 가중치는
  **좋은 값이 점수를 깎게** 만든다. 둘 다 오류도 경고도 없었다.
  `total_score` 는 `skip_reason` 을 남기고, 배치(`jobs/scores.load_weights`)는
  **기본값으로 되돌리고 말한다** — 설정 한 줄 때문에 그날 추천을 통째로 비울 수는 없다.
  범위는 `web/lib/settings.ts` 의 `percent` 가 정의처이고 테스트가 두 수를 대 본다
- **가중치가 추천을 얼마나 좌우하는지는 리포트가 보여 준다** (2026-10-04, docs/reports.md 3.2, infra 25.947). 1부 종목마다
  설정 가중치를 ±10%p·팩터 빼기·센티먼트 끔으로 흔든 열여섯 세계 가운데 몇에서 상위 5 에 남는지를 적는다. 점수는 그대로다

## 6. 저장 스키마 (마이그레이션 0007 예정)

설계서 3.3 절의 정의를 그대로 따른다.

```sql
CREATE TABLE factors (
    id            INTEGER PRIMARY KEY AUTOINCREMENT,
    stock_id      INTEGER NOT NULL REFERENCES stocks (id),
    as_of_date    TEXT NOT NULL,
    factor        TEXT NOT NULL,     -- value quality growth momentum risk
    raw_json      TEXT,              -- 원시 지표와 그때 쓴 창
    zscore        REAL,
    score         REAL,              -- 0~100
    peer_group    TEXT NOT NULL,     -- market:KOSPI / sector:KOSPI:반도체
    peer_size     INTEGER NOT NULL,  -- 그 집단의 유효 표본 수
    missing_fields TEXT,             -- JSON 배열
    calc_version  INTEGER NOT NULL,
    created_at    TEXT NOT NULL,
    UNIQUE (stock_id, as_of_date, factor, calc_version)
);

CREATE TABLE scores (
    id              INTEGER PRIMARY KEY AUTOINCREMENT,
    stock_id        INTEGER NOT NULL REFERENCES stocks (id),
    as_of_date      TEXT NOT NULL,
    total_score     REAL,            -- 산출 불가면 NULL
    factor_scores   TEXT NOT NULL,   -- JSON
    sentiment_score REAL,
    sentiment_weight_used REAL NOT NULL,
    weights_json    TEXT NOT NULL,   -- 그때의 가중치 스냅샷
    rank_in_market  INTEGER,
    rank_in_sector  INTEGER,
    skip_reason     TEXT,            -- 점수를 내지 않은 사유
    calc_version    INTEGER NOT NULL,
    created_at      TEXT NOT NULL,
    UNIQUE (stock_id, as_of_date, calc_version)
);
```

`peer_size` 와 `skip_reason` 은 설계서에 없던 컬럼이다. "왜 이 점수인가"와
"왜 점수가 없는가"를 DB만 보고 답할 수 있어야 해서 넣는다.

| 입력 | 정의 | 근거·한계 |
|---|---|---|
| 상장일 `listed_date` | **가격 이력의 관측 첫 거래일** (`MIN(prices.date)`) | 실제 상장일이 아니다. 5년 백필 창보다 오래 상장한 종목은 창 시작일이 들어간다. "상장 1년 이상" 판정에는 충분하다 |

BRK 처럼 옛 값만 남은 회사·해외 발행사는 NULL → 시총 결측으로 탈락 |

## 10. 2026-09-17 추가 지표 — 근거와 정한 값

사용자 요청("최근 트렌드나 획기적인 지표를 더하자")에 대한 답이다. 전제는 그대로다:
**저장된 실제 수치만, 계산식은 여기 먼저, 손으로 검산한 테스트와 함께.**

무료로 얻을 수 있는 "최신 트렌드" 데이터는 거의 없다(구글 트렌드는 공식 API 가 없고,
소셜 API 는 유료, 애널리스트 추정치도 유료). 그래서 **학계에서 검증됐는데 이 엔진에
없던 지표**를 더했다. 전부 이미 저장된 가격·거래량·재무제표로 계산된다.

### 10.1 가격·거래량 지표 (A 묶음)

| 지표 | 팩터 | 근거 | 이 엔진에서 정한 것 |
|---|---|---|---|
| 52주 고점 근접도 | 모멘텀 | George & Hwang (2004), *Journal of Finance*. 52주 고점에 가까운 종목이 이어서 오르는 경향이 12-1 모멘텀과 별개로 있다 | **종가 기준**이다. 장중 고가는 백테스트 가격 창에 없고, 종가 기준이 더 보수적이다. 252 거래일이 다 있어야 하며 모자라면 NULL |
| 꾸준함 (정보 이산성) | 모멘텀 | Da, Gurun & Warachka (2014), *Review of Financial Studies*, "Frog in the Pan". 같은 수익률이라도 조금씩 꾸준히 쌓인 쪽이 이어진다 | 원 논문의 ID 는 수익률 부호를 곱해 방향이 조건부다. 여기서는 단조 지표가 필요해 `양수일 비율 − 음수일 비율` 로 **단순화**했다. 꾸준히 오른 종목은 양수, 하루 급등으로 오른 종목은 0 근처다. 12-1 창(252일)의 일간 수익률이 126개 미만이면 NULL |
| 변동성 조정 모멘텀 | 모멘텀 | Barroso & Santa-Clara (2015), *Journal of Financial Economics*. 모멘텀의 위험을 변동성으로 나누면 붕괴가 줄어든다 | 원 논문은 포트폴리오 수준의 스케일링이다. 여기서는 종목별 `12-1 수익률 / 연환산 변동성` 으로 옮겼다(실무에서 흔한 변형). 변동성이 0 이면 NULL |
| Amihud 비유동성 | 리스크(안정성) | Amihud (2002), *Journal of Financial Markets*. `|수익률| / 거래대금` 의 평균. 클수록 거래가 가격을 흔든다 | 개인 투자자에게는 **빠져나올 수 있는지**의 문제라 안정성 축에 넣었다(높을수록 나쁨). 창은 63 거래일 — 유동성은 변하므로 최근 상태를 본다. 거래대금이 있는 날이 30일 미만이면 NULL. 단위는 "거래대금 10억당 수익률" 이라 국내(원)·미국(달러)의 절대값은 다르지만 z-score 는 시장 안에서만 내므로 상관없다 |

**창 길이와 하한의 근거.** 252·63 은 기존 모멘텀·성과지표와 같은 창이다(새 숫자를 만들지
않았다). "절반(126일)" 과 "30일" 은 `docs/metrics.md` 의 표본 하한 사고방식을 따른 여유값이다
`[확인필요: 실측으로 조정]`.

**백테스트에서도 같은 식으로 낸다.** 가격 창(`PriceView`)에 거래대금을 함께 실어 Amihud 도
t-1 까지의 값으로 계산한다. 어느 지표든 적재 경로와 백테스트 경로의 계산식은 하나다
(`services/scoring.price_series_metrics`).

**바뀐 것.** 모멘텀 팩터가 3개 지표 평균에서 6개 평균이, 리스크가 7개에서 8개가 됐다.
`CALC_VERSION` 을 2 로 올렸다. 과거 행은 그대로 두고 새 버전으로 쌓는다.

**검증 계획.** 지표마다 손으로 검산한 테스트(`tests/test_scoring.py`)가 있다. 유효성은
백테스트의 팩터별 단일 전략(성과요인분석)으로 넣기 전·후를 같은 코드로 비교한다.
DB 한도가 풀리면 돌린다(`docs/infra.md` 23절). **결과가 좋아 보여도 절대값을 믿지 않는다.**

### 10.2 재무제표 지표 (B 묶음)

전부 `financials`(적재)와 `financial_snapshots.payload`(백테스트)에 **이미 있는 컬럼**으로 낸다.
DART 는 유동자산·유동부채·비유동부채를 주고(`sources/dart.py`), SEC 는 `AssetsCurrent`
`LiabilitiesCurrent` 를 준다(`sources/sec_facts.py`). 새 수집은 없다.

| 지표 | 팩터 | 근거 | 이 엔진에서 정한 것 |
|---|---|---|---|
| 자산 성장률 | 퀄리티 (**낮을수록 좋음**) | Cooper, Gulen & Schill (2008), *Journal of Finance*, "Asset Growth and the Cross-Section of Stock Returns". 총자산이 빨리 불어난 기업의 이후 수익률이 낮다. Fama-French 5팩터의 CMA(보수적 투자) 축과 같은 현상 | "성장" 팩터가 아니라 **퀄리티**에 넣었다. 성장 팩터는 "커지고 있는가"(+)인데 이 지표는 방향이 반대라, 같은 팩터에 넣으면 평균에서 서로 지운다. 전년 총자산이 0 이하면 NULL |
| 유동비율 | 퀄리티 | 전통적 단기 지급능력 지표. 피오트로스키(2000)의 F-score 구성 요소이기도 하다 | `current_liabilities` 가 0 이하면 NULL. **은행·보험은 유동/비유동 구분을 하지 않아** 두 컬럼이 비고 자연히 NULL 이 된다 — 그 업종에서는 이 지표 없이 나머지로 퀄리티를 낸다 |
| 피오트로스키 축소판 | 퀄리티 | Piotroski (2000), *Journal of Accounting Research*. 9개 이진 신호의 합(F-score)이 높은 가치주가 낮은 가치주를 이긴다 | 원본 9개 중 **저장 컬럼으로 낼 수 있는 6개**만 쓴다(아래). 영업현금흐름·발생액·유상증자·**매출총이익률**은 컬럼이 없어 뺐다(매출총이익률은 영업이익률로 **대체**). 6개 중 **하나라도 판정할 수 없으면 전체를 NULL** 로 둔다 — 부분 합은 낮은 쪽으로 치우쳐 "모르는 것"이 "나쁜 것"으로 읽힌다 |

**피오트로스키 축소판의 6개 조건** (당해 = 최근 사업연도, 전년 = 그 전 사업연도. 둘 다 연결·연간)

| # | 조건 | 계산 | 원본과 다른 점 |
|---|---|---|---|
| 1 | ROA > 0 | `net_income / total_assets > 0` | 원본은 기초 총자산으로 나눈다. 여기서는 당해 총자산 (기존 ROA 와 같은 식) |
| 2 | ROA 개선 | `ROA당해 > ROA전년` | 〃 |
| 3 | 레버리지 감소 | `noncurrent_liabilities / total_assets` 가 전년보다 **작다** | 원본은 장기차입금. 컬럼이 없어 **비유동부채**로 대신한다. 비유동부채가 **두 해 다** 있지 않으면 두 해 모두 **부채총계**로(`scoring._leverage_pair`). 부채총계도 두 해 다 있지 않으면 판정 불가. 같은 종목의 두 해는 반드시 같은 잣대다 |
| 4 | 유동비율 개선 | `유동비율당해 > 유동비율전년` | 없음 |
| 5 | 이익률 개선 | `operating_income / revenue` 가 전년보다 크다 | 원본은 매출총이익률. 컬럼이 없어 **영업이익률**로 대신한다 (미국은 9.2 절대로 세전이익 대리가 들어올 수 있다) |
| 6 | 자산회전율 개선 | `revenue / total_assets` 가 전년보다 크다 | 원본은 기초 총자산. 여기서는 당해 총자산 |

빠진 3개(영업현금흐름 > 0, 발생액 = CFO > 순이익, 유상증자 없음)는 현금흐름표·주식수 이력이
없어 낼 수 없다. **컬럼이 생기면 그때 더한다** — 지금 흉내 내지 않는다.

**바뀐 것.** 퀄리티 팩터가 5개 지표 평균에서 8개 평균이 됐다. 반쪽 규칙은 8개 중 4개.
`CALC_VERSION` 을 3 으로 올렸다. 적재(`jobs/scores.build_inputs`)와 백테스트
(`jobs/backtest.build_pit_inputs`)는 같은 `services/scoring.statement_metrics(current, previous)`
를 부른다.

**알려진 한계.** ① 국내 재무는 최근 몇 년만 있어 전년 값이 없는 종목은 자산 성장률과
피오트로스키가 NULL 이다 — 백테스트 초반 구간은 특히 그렇다 ② 미국은 영업이익 결측 21%
(9.2 절)만큼 조건 5 를 못 내 피오트로스키 NULL 이 는다 ③ 피오트로스키는 0~6 정수라
z-score 가 계단이 된다. 집단이 작으면 같은 값이 몰려 순위가 뭉친다 `[확인필요: 실측]`.

## 11. 2026-09-21 추가 지표 — 배당·잔차 변동성·MAX·SUE

사용자 요청("적용은 안 되어 있지만 적용하면 좋을만한 것")에 대한 답이다. 10장과 같은 전제다:
**저장된 실제 수치만, 계산식은 여기 먼저, 손으로 검산한 테스트와 함께.**

### 11.0 먼저 — **지표를 더하면 기존 지표가 묽어진다**

팩터 점수는 그 팩터에 속한 지표 z-score 의 **평균**이다(2.2절). 그래서 지표를 하나 더하면
기존 지표 각각의 몫이 줄어든다. 모멘텀은 3개에서 6개가 됐고(10장), 퀄리티는 5개에서 8개가 됐다.

**그래서 이번에는 근거가 센 것만, 축마다 하나둘씩만 더한다.** 넣고 싶었지만 뺀 것도 아래 적는다.
넣은 뒤의 유효성은 **백테스트의 팩터별 단일 전략**으로 넣기 전·후를 같은 코드로 비교해 본다
(10장과 같은 방식). DB 한도가 풀리면 돌린다.

### 11.1 배당 — **이미 모으고 있는데 점수에 한 번도 안 썼다**

3.1 절에 이렇게 적혀 있었다.

> EV/EBITDA 와 **배당수익률은 넣지 않는다.** 현금·차입금·**배당 컬럼이 `financials` 에 없다**

**그 전제가 바뀌었다.** 마이그레이션 `0013_stock_dividends.sql` 로 전용 표가 생겼고,
국내(`jobs/dividends.py`, DART 배당에 관한 사항)와 미국(`jobs/us_financials.py`, SEC 배당 태그)
**양쪽 다** 쌓는다. 그런데 그것을 읽는 곳은 `jobs/accumulation.py`(장기 적립) 하나뿐이었다 —
**점수·신호는 배당을 한 번도 본 적이 없다.**

| 지표 | 팩터 | 계산식 | 입력 | 방향 |
|---|---|---|---|---|
| 배당수익률 `dividend_yield` | **밸류** | `cash_dividend_total / market_cap` | stock_dividends, universe_members | + |
| 배당 연속성 `dividend_years` | **퀄리티** | 최근 5개 사업연도 중 `cash_dividend_total > 0` 인 연수 ÷ 관측 연수 | stock_dividends | + |

**왜 `dps_common` 이 아니라 `cash_dividend_total` 인가.** 주당배당금은 액면분할이 있으면
해마다 비교할 수 없다(표 주석에 그렇게 적혀 있다). 총액은 분할의 영향을 받지 않고,
**분모를 시가총액으로 두면 E/P·B/P·S/P 와 같은 모양**이 된다 — 밸류 축의 다른 지표와 잣대가 같다.

**무배당은 0 이고 NULL 이 아니다. 단, 그 종목 행이 아예 없으면 NULL 이다.**
배당을 안 주는 것은 **아는 사실**이지 모르는 것이 아니다. 그런데 아직 수집이 닿지 않은 종목과
구별해야 한다. 그래서 규칙은 이렇다.

- `stock_dividends` 에 그 종목 행이 **하나라도** 있으면 → 최신 사업연도 값을 쓰고, 그 해에
  배당이 없으면 **0**
- 행이 **아예 없으면** → **NULL**(모름). 수집이 안 닿은 것과 무배당을 같게 보지 않는다(25.74 와 같은 규칙)
- **미국은 10-K 가 기준이다** (2026-09-28, infra 25.557). SEC 수집은 배당 태그가 없는 해에 행을 만들지 않으므로,
  그 기준일에 알 수 있던 **가장 최근 10-K 연도에 배당 행이 없으면 0**(무배당·배당 중단)이다. 10-K 는 **제출일이 기준일보다
  앞선 것만** 센다 — 배당 행은 제출 다음 거래일부터 보이기 때문이다(25.561). 적재와 백테스트가 `scoring.us_dividend_or_zero`
  한 함수를 쓴다. 10-K 가 없으면 NULL.
  배당 행을 하나도 못 읽었으면(표 없음·수집 전·읽기 실패) 채우지 않는다. 배당 태그를 다른 이름으로 단 회사는
  무배당으로 읽힌다 `[확인필요]`

**배당 연속성**은 `profit_stability`(이익 안정성)와 같은 모양이다 — 관측 연수가 **3년 미만이면 NULL**.

**배당성향(`payout_ratio`)은 넣지 않는다.** 단조가 아니다. 적당히 높은 것은 좋지만 너무 높으면
이익을 넘겨 배당한다는 뜻이라 오히려 나쁘다. z-score 는 단조 지표를 전제하므로 그대로 넣으면
"가장 위험한 회사가 가장 좋은 회사"로 올라온다. 구간 점수로 바꾸는 길이 있지만 문턱을
정할 근거가 없어 **[확인필요]로 두고 뺀다.**

### 11.2 MAX 효과 — 지난 한 달의 **최대 일간 수익률**

| 지표 | 팩터 | 계산식 | 입력 | 방향 |
|---|---|---|---|---|
| `max_daily_return` | **리스크(안정성)** | 최근 21 거래일 일간 수익률의 **최댓값** | prices | **−** |

Bali, Cakici & Whitelaw (2011), *Journal of Financial Economics*, "Maxing Out: Stocks as
Lotteries and the Cross-Section of Expected Returns". 지난 한 달에 **하루 크게 튄** 종목은
이후 수익률이 낮다. 복권 같은 종목에 사람이 웃돈을 준다는 설명이다.

**이미 있는 지표와 다르다.** 변동성은 **퍼짐**을 보고 MAX 는 **한 번의 꼬리**를 본다.
꾸준함(`momentum_consistency`)과도 다르다 — 그쪽은 12-1 창(252일)의 부호 비율이고
이쪽은 최근 21일의 크기다.

- 21 거래일은 `MOMENTUM_SKIP_DAYS` 와 **같은 창**이다(새 숫자를 만들지 않았다)
- 일간 수익률이 **10개 미만이면 NULL**
- 수정주가를 쓴다(3.4 절과 같다). 분할이 가짜 급등으로 잡히면 안 된다

### 11.3 잔차 변동성 (Idiosyncratic Volatility)

| 지표 | 팩터 | 계산식 | 입력 | 방향 |
|---|---|---|---|---|
| `idio_volatility` | **리스크(안정성)** | 시장모형 잔차의 표본표준편차 × √252, **최근 252 거래일** | prices, index_prices | **−** |

Ang, Hodrick, Xing & Zhang (2006), *Journal of Finance*, "The Cross-Section of Volatility and
Expected Returns". 시장으로 설명되지 않는 변동이 **큰** 종목이 이후 수익률이 낮다.

**계산 순서** (베타와 같은 재료를 쓴다 — `services/metrics.align`, `daily_returns`)

1. 종목과 지수의 **겹치는 날**만 남긴다. 날짜를 안 맞추면 값이 통째로 틀린다(3.5 절 베타와 같다)
2. 일간 수익률 `r_i`, `r_m` 을 낸다
3. 최소제곱으로 `β = cov(r_i, r_m) / var(r_m)`, `α = mean(r_i) − β·mean(r_m)`
4. 잔차 `e_t = r_i,t − (α + β·r_m,t)` 의 **표본**표준편차에 `√252` 를 곱한다

- **창은 252 거래일**(1년, `IDIO_WINDOW_DAYS`). 겹치는 수익률이 더 많으면 **최근 것부터 252개**만 본다
- 겹치는 날의 수익률이 **60개 미만이면 NULL** (`MIN_BENCHMARK_POINTS` 와 같은 값).
  창은 **상한**이고 이것은 **하한**이다
- 자르는 일은 `services/scoring.idio_volatility` **안에서** 한다. 부르는 쪽(적재·백테스트)이
  각자 자르면 갈라진다 — 2026-09-21 까지 실제로 갈라져 있었다(`docs/infra.md` 25.99)
- `var(r_m) = 0` 이면 NULL — 회귀가 성립하지 않는다

> SUE 를 잇는 것은 "종목선정 기법 발굴 루프"(CLAUDE.md) 1회차에서 **조건부 통과** — 국내만, 백테스트 전략으로
> 먼저 넣는다. 발표 전후 초과수익(EAR)은 잠정실적 공시일이 없어 보류

지금 중기 신호(`docs/signals.md` 1.2)는 **연간** 실적 성장만 본다. 사업보고서 기준이라
**1년에 한 번만 바뀐다.** "실적 모멘텀" 이라는 이름에 비해 너무 느리다.

| 지표 | 쓰는 곳 | 계산식 | 입력 |
|---|---|---|---|
| `sue` | 중기 신호(점수 아님) | `(당분기 EPS − 4분기 전 EPS) / stdev(최근 8개 분기의 전년동기 대비 변화)` | financials (`period_type='Q'`) |

Bernard & Thomas (1989), *Journal of Accounting and Economics*. 실적 발표 뒤 주가가 며칠에
걸쳐 같은 방향으로 밀리는 현상(PEAD)이고, 가장 오래 살아남은 이상현상 중 하나다.

**4분기 전과 견주는 이유**는 계절성이다. 유통·건설처럼 분기마다 모양이 다른 업종에서
직전 분기와 견주면 계절 변동이 실적 변화로 읽힌다.

- 전년동기 대비 변화가 **8개 미만이면 NULL** (분기 12개가 필요하다)
- 표준편차가 0 이면 NULL — 한 번도 안 변한 실적에서 "몇 표준편차" 는 뜻이 없다
- 중간에 모르는 분기가 있으면 그 변화는 NULL 이고 **자리를 유지한다.** 솎아 내면 뒤의 값이
  앞으로 당겨져 "최근 8개" 가 3년 전 것을 섞는다
- EPS 는 `net_income / 주식수` 인데 **주식수 이력이 없다.** 그래서 당장은 `net_income` 자체의
  전년동기 대비 변화를 **시가총액으로 나눠** 쓴다 — 주식수 변화가 없다는 가정이고,
  유상증자가 있으면 틀린다. 그 한계를 `raw_json` 에 적는다 `[확인필요: 주식수 수집]`
- **그런데 시가총액이 하나뿐이면 그 나눗셈은 약분돼 사라진다.** 분자도 분모도 같은 값으로
  나뉘기 때문이다(SUE 는 원래 단위가 없는 값이다). 지금 시가총액이 하는 일은 **0 이하를
  걸러내는 문지기**뿐이다. 분기마다 다른 시가총액을 쓰게 되면 그때는 약분되지 않는다 —
  **없는 효과를 있다고 적어 두면 다음 사람이 그것을 믿는다**
- **분모에 당분기 변화가 들어간다.** 표준(Foster 1977)은 **이전** 8개로 정규화한다.
  그쪽이 큰 서프라이즈가 제 분모를 부풀리지 않아 더 날카롭지만 분기가 13개 필요하다.
  지금은 분기 수집 자체가 없어 재어 볼 수 없다 `[확인필요: 켠 뒤 둘을 나란히 본다]`

**계산식은 이미 있다** (2026-09-21): `services/scoring.sue` · `services/scoring.yoy_changes`,
`tests/test_scoring_new_metrics.py` 에 손으로 검산한 값과 함께. **팩터에는 등록하지 않았다** —
값이 늘 NULL 인 지표를 등록하면 절반 규칙의 분모만 키워 멀쩡한 종목의 점수를 지운다
(`docs/infra.md` 25.92). 쓰는 곳도 팩터가 아니라 중기 신호다.

`tests/test_scoring_new_metrics.py::TestSUE_는_아직_안_쓴다` 가 **`jobs/financials.py` 가
반기(`11012`)·분기(`11013`) 보고서를 받기 시작하는 순간 깨진다.** 그때가 이을 때다 —
"나중에 하자" 를 사람의 기억이 아니라 테스트에 맡긴다.

> **오늘은 늘 NULL 이다.** `jobs/financials.py` 가 사업보고서(`11011`)만 받는다. 분기를 받으면
> 수집량이 네 배가 되고 지금은 D1 하루 쓰기 한도 안에서 국내 시세도 못 다 채우고 있다

**업종 모멘텀 (1회차 D, 2026-09-28, docs/infra.md 25.439)** — `batch/services/sector_momentum.py`

| 무엇 | 식 |
|---|---|
| 업종 평균 | 같은 시장·같은 업종(`stocks.sector`) 종목들의 `momentum_12_1` 동일가중 평균. 값이 있는 종목이 **30 미만**(`MIN_PEER_SIZE`, 업종 z-score 최소 집단과 같은 값)인 업종은 내지 않는다 |
| 상위 절반 | 시장마다 업종 평균 순위 상위 절반(올림) |
| 조건 | 그 종목의 업종이 상위 절반이면 통과. **업종 평균을 낼 수 없는 종목(업종 없음·작은 업종)은 조건을 적용하지 않는다** — 모르는 것으로 자르지 않는다 |

- **팩터가 아니다.** 업종 z-score 안에서는 모두 같은 값이라 z=0 이 된다. 신호 조건으로만 쓴다
- 잰다: 백테스트 전략 `momentum_sector`(모멘텀 팩터 상위 N 을 조건 통과 종목 안에서만)를 `momentum` 과 비교하고,
  IC 이름 `sector_mom`(종목마다 그 업종 평균)을 본다. 켜는 기준(12장 머리)을 넘으면 단기 신호 조건으로 넣는다
- 한계: 업종은 오늘 분류를 과거에도 쓴다(backtest.md 1.3), 12-1 이라 최근 1개월 효과는 빠진다(1회차 검증 2)
- **업종 채움이 60% 미만인 동안은 판정하지 않는다** (25.443, 교차검증). 업종 평균을 낼 수 없는 종목은 조건을 통과하므로,
  채움이 22% 수준(factors.md 7.1)이면 약 95% 가 통과해 `momentum` 과 사실상 같은 종목을 고른다. 백테스트가 그 비율을
  재서 60% 미만이면 결과에 "판정 불가" 경고를 붙인다. IC `sector_mom` 도 표본 비율 문턱(25.442)에 걸려 판정 불가가 된다

**발생액 (1회차 C, 2026-09-28, docs/infra.md 25.440·25.444·25.445)** — `batch/services/earnings_quality.py`

| 무엇 | 식 |
|---|---|
| 발생액 비율 | (순이익 − 영업활동 현금흐름) / ((당기 총자산 + 전년 총자산) / 2). 방향 −(작을수록 좋다) |
| 결측 | 하나라도 없거나 평균 총자산 ≤ 0 이면 NULL. **전년 총자산을 당기로 대신하지 않는다**(인수합병 해에 부푼다) |
| 시점 | 백테스트는 기준일(t-1)까지 나온 공시만(`pit_financials`) — 최근 연도와 전년도 스냅샷 |

- 지금은 **미국만** 값이 있다(SEC CFO, 25.440·25.444). 국내는 현금흐름표를 받지 않아 NULL — IC 표본 비율 문턱(25.442)에
  걸려 국내는 판정 불가가 된다
- **Sloan(1996) 의 원래 정의와 다르다** (25.448, 교차검증). Sloan 은 재무상태표 기반 **유동(운전자본) 발생액 − 감가상각비**다.
  여기 식은 현금흐름표 기반 **총발생액**(Hribar & Collins 2002 방식)이라 효과 크기·비교 기준이 다르다
- **금융업은 뺀다** (25.452). 영업현금흐름을 트레이딩 자산·대출 변동이 좌우해 발생액이 이익의 질을 뜻하지 않는다.
  재무상태표 방식은 유동자산·부채가 없어 자동으로 빠지지만 이 식은 아니다. 금융업 = `stocks.sector_code` 가
  **SIC 60~69**(Fama-French 관례: 은행·여신·증권·보험·부동산·지주/투자회사) 또는 **KSIC 64~66·68**(부동산 — 미국 SIC 65 와 맞춘다, 25.457)(`sectors.is_financial`). 두 나라 모두 지주회사가 빠진다(SIC 67, KSIC 64 안의 지주회사).
  업종 코드가 없는 종목은 모르는 것이라 남긴다. IC 표본 비율의 분모도 **금융업을 뺀 후보**다 — 일부러 뺀 종목을
  "값이 비었다" 로 세면 문턱이 금융 비중만큼 까다로워진다. 업종 코드 채움이 낮으면 금융업이 덜 빠진다 `[확인필요: 미국 채움률]`
- 영업현금흐름은 **합계 태그만** 쓴다. 계속영업 태그로 넘어가면 순이익(중단영업 포함)과 기준이 어긋난다(25.448)
- 같은 연도에 정정 공시(10-K/A)가 손익·재무상태만 다시 냈으면 **앞 공시의 영업현금흐름으로 빈 칸을 메운다**
  (`backtest.year_values`, 둘 다 기준일 전 공시)
- **살아남은 종목 쪽으로 기운다.** 옛 스냅샷 채우기(25.444)는 수집 대상(오늘 active + 거래대금 후보)만 채운다 —
  그 뒤 떨어진 종목의 과거 스냅샷은 영업현금흐름이 비어 있다
- 잰다: IC 이름 `accrual`(−발생액). 후보 전략은 IC 가 판정 가능해진 뒤 넣는다(퀄리티의 한 지표를 바꾸는 실험, 검증 2)
- 주의: cash_roa(CFO/총자산)는 ROA 와 겹쳐 1회차에서 탈락했다. 이것과 다르다

**순주식발행 (1회차 B, 2026-09-28, docs/infra.md 25.446·25.450)** — `batch/services/share_issuance.py`

- **국내 검토 (2026-09-28, docs/infra.md 25.468).** 새 표(마이그레이션) 없이 되는 길을 찾았다. 아직 잇지 않았다.
  - 기각: 한국거래소 일별 `LIST_SHRS` 는 날마다 오지만 `prices` 에 담을 열이 없다(열 추가는 마이그레이션). `universe_members.market_cap`
    ÷ 종가는 유니버스를 만든 뒤(2026-09)부터라 백테스트 창이 없다
  - 채택 후보: DART **주식의 총수 현황**(`stockTotqySttus`, 사업보고서 기준) — 발행주식총수·자기주식수. 한 회사·한 해에 호출 1번
    (유니버스 약 880 × 5해 ≈ 4,400회, DART 하루 한도 안). 값은 연간 스냅샷 payload 에 열쇠를 더해 담는다(미국 25.444 와 같은 채우기).
    시점 = 그 사업보고서 접수일
  - 필드(25.474 정정): 발행주식총수는 `istc_totqy`, 자기주식수는 `tesstk_co`, 유통주식수는 `distb_stock_co` 다.
    `isu_stock_totqy` 는 **발행할** 주식의 총수(정관 한도)라 쓰면 안 된다 `[확인필요: 실제 응답]`
  - 분할: DART 값은 조정 전이다. **국내 수정주가 계수 전체로 나누면 안 된다** (25.474, 교차검증). `adjust_kr` 의 계수는
    분할·병합뿐 아니라 무상·유상증자 **권리락**도 잡는다(docs/adjust.md). 30% 주주배정 유상증자(할인 25%)는 주식수 1.3배·계수
    약 1.061 → 계수로 나누면 순발행 0.20(참값 0.26)으로 희석을 덜 센다. 게다가 제3자배정·일반공모는 권리락이 없어 온전히 잡혀
    증자 방식마다 값이 어긋난다. 그래서 **정수비에 가까운 날의 계수만** 곱한다 — 1/계수 또는 계수가 정수에 2% 안인 날(분할·병합·
    1:1 무상증자). 무상증자를 발행으로 세지 않는 것은 돈이 들어오지 않아서다. 정수비가 아닌 무상증자(0.5:1 등)는 빠진다 `[확인필요: 빈도]`
  - 식: ln((발행 − 자기주식)_t / ((발행 − 자기주식)_{t−1} × 분할배수)). 자기주식을 빼는 것은 소각 전 매입도 줄어든 것으로 보기 위해서다
  - **미국과 정의가 다르다**: 미국은 같은 10-K 의 가중평균 주식수, 국내는 연말 유통주식수다. IC 이름을 `net_issuance_kr` 로 따로 둔다
  - 잇기 전에 볼 것 `[확인필요]`: 응답의 주식 종류(보통·우선) 행 구분, 결산월이 12월이 아닌 회사, 결측률, 정기보고서 API 가
    정정본 값을 원래 접수일에 붙여 주는지(그러면 미래 정보), 인적분할·자사주 활용 회사의 튀는 값

- `quality_op_assets` 는 **나라 계열 `op_assets~roa` 상관 평균(시장별 값의 단순 평균)이 0.9 이상이면 판정하지 않는다**("사실상 같은 지표") — 규칙을 넘어도 "판정 불가(겹침)" 로 적는다. 기계적으로 한다 — `factor_ab.OVERLAP_GATE`
- 퀄리티 교체가 둘 이상 통과하면(3회차 E 의 매출총이익 교체 실험 포함) B − A 평균이 큰 쪽 **하나만** 채택 후보로 둔다
- `risk_drop_idio` 는 통과해도 리스크 구성을 자동으로 바꾸지 않는다(9회차 3 과 같은 이유 — 리스크 축은 CLAUDE.md 가 정의한 성과 지표 묶음). 결과와 함께 handoff 에 적는다
- 변형이 3 → 5 개가 되어 판정 횟수가 는다. 3회차가 적은 거짓 통과 약 11% 경고가 그대로 적용된다 — 원 논문 방향과 맞는지 함께 본다
- `CALC_VERSION` 은 올리지 않는다(운영·전략 결과가 같다). 비용은 검증 B 실측으로 리밸런스당 미국 약 0.4초·국내 약 0.12초 늘어난다(60개월이면 약 25초·7초)
