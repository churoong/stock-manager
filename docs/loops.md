# 에이전트 루프 (루프 엔지니어링)

> 2026-10-23 사용자 지시: "우리가 구성한 여러 에이전트들을 통해 루프 엔지니어링이 구현되어야해". docs/infra.md 25.1751.
> 그 전에는 루프가 CLAUDE.md 문장과 주 세션의 기억에 기대 있었다 — 역할 지시문을 매번 새로 썼고, 정기 실행은 주간 발굴 하나뿐이었다.
> 이제 **역할은 `.claude/agents/`, 루프 한 회차의 흐름은 `.claude/workflows/`, 언제 도는지는 예약 실행, 문(gate)·멈춤 조건은 이 문서**에 고정한다.
> 설정이 썩지 않게 `tests/test_loop_config_1751.py` 가 본다(에이전트 이름·도구, workflow 가 부르는 에이전트·phase·문법, 이 문서가 모두를 적었는지).

## 0. 원칙

- **찾는 쪽과 고치는 쪽을 가른다.** 역할 에이전트는 모두 **읽기 전용**(정의 파일 도구에 Edit·Write 없음)이다. 단 대체 경로(아래 1장 — 범용
  에이전트가 정의 파일을 읽음)는 도구 제한이 없어 **지시문으로만** 지킨다. 그래서 주 세션은 workflow 를 마친 뒤 `git status`·`git worktree list` 가 그대로인지 본다. 고치기·시험·되돌리기 확인·기록·커밋·푸시는 **주 세션**이 한다
  (CLAUDE.md "한 건의 끝"). 에이전트가 낸 결함은 다른 에이전트가 반박한 뒤에만 고친다
- **Bash 가 있어 등록된 역할도 저장소를 바꿀 수 있다**(25.1759 — 나란히 돈 교차검증 렌즈의 worktree 이름이 겹쳐 사라졌고, cd 가 실패해 본체에서
  sed·checkout 이 돌았다; 그때 주 세션은 커밋을 마친 뒤라 잃은 것은 없었다). 그래서: 역할은 `mktemp -d` 로 worktree 이름을 짓고 명령마다 `cd "$W" || exit 1`,
  주 세션은 **커밋을 마친 뒤에** workflow 를 돌린다(커밋 안 된 작업을 에이전트가 덮을 수 없게)
- **루프 하나 = workflow 하나 + 주 세션의 마무리.** workflow 는 사람이 아니라 문으로 끝난다: 발굴은 "두 검증 보수적 합침", 결함은 "반박에서 진짜", 교차검증은 "[필수] 합계"
- **예산**: 한 workflow 에 에이전트 10 아래(세션 기준). 넘는 후보·결함은 버리지 않고 결과의 `skipped` 로 다음 회차에 넘긴다(소리 없는 자르기 금지)
- **비용 0원**: 에이전트는 이 구독 안에서 돈다. 유료 API·Actions 분을 쓰지 않는다. 에이전트는 Turso·운영 DB·네트워크를 조회하지 않는다
- **창과 달 규칙을 먼저 본다**: `docs/handoff.md` 머리의 금지 창(예: 11-03 15:00 UTC ~ 11-04 06:00 UTC — 푸시·웹 백테스트·무거운 Turso 금지)과 달 규칙
  (10월 — Turso 읽기·db-status·운영 수동 실행 자제. "10월 마이그레이션 커밋 금지" 는 2026-10-28 사용자 지시로 지웠다 — 25.1896). 창 안이면 루프는 **로컬 커밋까지만** 하고 푸시는 창 뒤에
- **판단은 파일에 남긴다**: 회차 결과는 `docs/infra.md` 25.x(결함·교차검증)·`docs/factors.md` 12장(발굴)·`docs/handoff.md`(다음 할 일)에. 대화에만 두지 않는다

## 1. 역할 에이전트 (`.claude/agents/`)

workflow 는 역할을 `역할('이름', …)` 으로 부른다 — 등록된 이름으로 먼저, 세션이 그 정의를 아직 읽지 않았으면(세션 시작 뒤에 더한 역할은 그 세션의 목록에 없다 —
25.1751 첫 실행에서 셋 다 "agent type not found") 범용 에이전트가 `.claude/agents/<이름>.md` 를 읽고 그대로 따른다. 정의는 그 파일 한 곳이다.

| 이름 | 역할 | 쓰는 루프 |
|---|---|---|
| `stock-discoverer` | 발굴 — 기존 12장 표와 겹치지 않는 운용·선정 후보 3~6개 | L1 |
| `stock-verifier-data` | 검증 A — 데이터·비용·시점(PIT)·근거표·코드 자리·읽기 비용 | L1 |
| `stock-verifier-stats` | 검증 B — 효용·중복·과최적화·표본·시도 수·사전 등록 문장 | L1 |
| `stock-defect-auditor` | 결함 감사 — 맡은 영역에서 재현 있는 결함 | L2 |
| `stock-refuter` | 반박 — 결함 주장 하나를 코드에서 다시 보고 틀렸다고 보이려 애씀 | L2 |
| `stock-cross-verifier` | 교차검증 — 커밋 범위를 렌즈 하나로 반박, 첫 줄 "[필수] N" | L3 |

## 2. 루프

### L1 발굴 루프 — `discovery-round`

- **언제**: 매주 월 10:47 KST 예약 실행(이 세션을 깨운다), 그리고 사용자가 발굴·아이디어를 지시했을 때
- **흐름**: 발굴 1 → 후보마다 검증 A·B 를 동시에(서로 결과를 보지 않음) → 보수적 합침(하나라도 탈락이면 탈락, 검증 하나가 죽으면 보류,
  사용자 지시분이 아니면 조건부 = 보류 — factors.md 12장 머리 동결 규칙)
- **주 세션 마무리**: 통과·조건부(지시분) 후보를 `docs/factors.md` 12장 새 회차 표·사전 등록 문단으로(코드보다 먼저) → 시점이 허락하면 꺼진 채 구현(IC 이름·백테스트 전략·기록만)
  → 시험·되돌리기 확인 → infra 25.x → L3 → 푸시. 지난 회차 후보 중 판정 실행 결과가 난 것은 켜는 기준으로 판정해 적는다
- **멈춤**: 후보 0 이면 "발굴 결과 없음" 을 12장에 한 줄. 결과에 `error`(발굴 에이전트가 죽음)가 있으면 그렇게 적지 않고 다시 돌린다. `skipped`(넘친 후보)는 다음 회차 발굴에 넘긴다. 판정 실행 전 금지 구간(예: 11-03 판정 실행 전 새 전략 코드)에는 사전 등록까지만
- **예산**: 1 + 2 × 4 = 9 (대체 경로는 등록 안 됨일 때만 타 에이전트 수가 늘지 않는다)

### L2 결함 루프 — `defect-round`

- **언제**: 평일 13:41 KST 예약 실행(국내 일일 배치 08:30 KST 뒤·미국 배치 전). 결함 묶음 사이 발굴과 번갈아(CLAUDE.md "결함 찾기와 나란히")
- **흐름**: 영역마다 감사 1 → 찾은 결함을 합쳐 같은 자리는 하나로 → 심각한 것부터 반박(상한 5) → 진짜만 돌려줌. 참고·넘친 것은 `skipped`
- **영역 회전표** (주 세션이 `areas` 로 둘씩 넘긴다 — 같은 영역을 매일 보지 않게):

  | 요일 | 영역 |
  |---|---|
  | 월 | 가상모의투자 장부·체결 판정 · 결정 원장·성과 분해 |
  | 화 | KIS모의투자 주문 경로·맞추기 · 실현손익·체결 비교 |
  | 수 | 매도 플래그·위험 점검 · 장중 감시 목록·알림 |
  | 목 | 일일 배치 흐름·텔레그램 리포트 · 운용 요약(desk)·관문 |
  | 금 | 웹 화면·API(`web/app/api`, `web/lib`) · 주간 요약·백테스트 판정 |

- **주 세션 마무리**: 진짜 결함마다 "한 건의 끝"(고침·시험·되돌리기 확인·infra 25.x·handoff·커밋) → 묶음이 차면 L3 → 전체 검사 → 푸시. `uncertain` 은 handoff 에 `[확인필요]` 로
- **멈춤**: 결과의 `clean` 이 참(진짜 0 · 죽은 감사 `failedAreas` 없음 · 반박이 죽은 `unrefuted` 없음)일 때만 infra 에 따로 적지 않고 handoff "결함 루프" 줄의
  날짜만 고친다(본 영역과 함께). `failedAreas`·`unrefuted` 가 있으면 그 영역·결함을 다음 회차에 다시 돌린다 — 죽은 감사를 "결함 0" 으로 적지 않는다(25.1752)
- **예산**: 감사 2~4 + 반박 ≤ 5

### L3 교차검증 루프 — `cross-verify`

- **언제**: 묶음 푸시 전 늘. **위험 커밋**이 들었으면 필수 — KIS 경로·일일 흐름·Actions 워크플로·마이그레이션·가상모의투자 주문 경로, 그리고
  L4 가 위험 모듈로 보는 장부·체결 판정(`services/paper.py`)·위험 점검(`risk_gate`)·손절·매도 플래그(`sell_flags`)(25.1752 — 두 목록이 달랐다)
- **흐름**: 렌즈 셋(돈·장부·주문 / 리포트·텔레그램·웹 / 기록·시험)이 같은 범위를 따로 반박 → `must` 합계. 렌즈 하나라도 결과가 없으면 `must = null`(통과로 치지 않는다)
- **문**: `must == 0` 이고 전체 검사(ruff·tsc·vitest·pytest rc 0·FAILED 0)가 통과해야 푸시. [필수] 가 있으면 고친 뒤 그 고침을 다시 L3
- **주 세션 마무리**: [권고]·[참고] 는 다음 25.x 에서 고치거나 남긴 까닭을 적는다
- **예산**: 3

### L4 돌연변이 점검 — `scripts/mutation_check.py`

- **언제**: 위험 모듈(장부·체결 판정·KIS 경로·위험 점검·손절)을 고친 묶음마다 로컬에서 한 번(약 3분, 25.1743). 금요일 결함 회차에 함께
- **문**: "18개 중 잡힘 18 · 문제 0"(25.1838 에 장중 감시 셋을 더함). 살아남은 것은 그 규칙을 이름으로 보는 시험을 더하는 건으로(25.1743 선례)
