> 사용자 말(2026-11-24): "이 시스템의 최종 목표는 최고의 실전 자동매매 시스템이야." → "이 시스템의 목적에 맞게끔 기법이나
> 매매전략, 관리 등 시스템의 모든 부분을 고도화 할 수 있는 아이디어를 물색하고 제시해."

겹침·이미 탈락·등록된 것을 걸러 모았다(infra 25.2273). **이 문서는 후보 목록이지 사전 등록이 아니다** — 전략·판정에 닿는 것은
발굴 회차(docs/loops.md L1)와 사전 등록을 거쳐야 하고, 수치 가운데 `[어림]`·`[확인필요]` 는 조사원이 운영 DB 를 보지 않고 낸 값이다.

## 0. 한 줄 진단

**가장 큰 병목은 전략 아이디어의 수가 아니라 "무엇이 진짜 통하는지 아는 속도" 와 "실전 주문을 맡길 안전 장치" 다.**
- 첫 문(리플레이 0→1)은 5년·시도 17 에서 연 정보비율 약 1.4 를 요구한다 `[어림]` — 진짜 실력(0.5)이 있는 전략도 약 2% 만 넘는다.
  11-03 첫 판정판에서 두 시장 통과가 0 이었던 것과 맞는다(infra 25.2178)
- 앞으로의 구간은 28일 묶음이 표본 하나라 한 달에 하나씩 쌓이고, 점수·규칙을 고치면 판이 올라 시계가 0 으로 돌아간다(H 는 6주에 판 1→2→3)
- 실전 준비 목록(docs/paper.md 14장)이 스스로 "없는 것" 으로 적은 장치가 남아 있다 — 체결 확인이 안 되면 다음 주문을 멈추는 장치, 나간 주문을 거두는 경로,
  매수만 멈춤, 절대 금액 한도, 정시 발주 깨움의 이중화

## 2. 영역별 나머지 후보

**전략·종목선정** (새 월간 상위-N 을 더 얹는 것은 값어치가 낮다 — 시도 수만 늘어 문턱이 오른다. 짝 차이·사건 단위·긴 역사로 판정되는 것 위주)
- 미국 업종 모멘텀을 넓은 업종 분류로(지금은 업종 채움 0.46 으로 매달 판정 불가 — `core_m` 미국 다리가 여기 묶여 있다)
- 이벤트 엔진의 관문 풀기 — `disclosures` 종류 칸·사건 표(37·41·46·47회차 후보 넷이 이 한 곳에서 막힘), 미국은 8-K 실적 항목
- 순위형 포트폴리오를 실제로 사는 계좌 — 주간 4갈래 엇갈림(리플레이에서 양인 "상위 20 월 리밸런스" 를 앞으로의 구간에서 재는 자리가 없다)
- 다자산 추세 슬리브(주식·국채·금·달러 ETF) — **CLAUDE.md ETF 예외 범위 밖이라 사용자 결정**
- 중기 "실적 모멘텀" 신호를 연간에서 분기로(지금은 최장 457일 묵은 연간 값)
- 단기 신호 조건 해체 검정(모멘텀 ≥ 60·거래대금 조건을 하나씩 뺀 그림자 규칙 — 두 재료가 우리 IC 에서 탈락)
- 수급 이력 깊이 탐침(KIS 가 30일보다 깊은 일별 이력을 주는지 — 주면 판정이 2029 에서 당겨진다)
- 하지 말 것: 분봉·호가 기반 단타 / 거시 지표 여럿으로 국면 분류기 / 생존편향 보정 전의 소형주 확장

**체결·위험관리**
- 주문 낸 종목만 그날 분봉 요약 저장(시가 단일가·지정가 닿은 시각·VWAP·종가 단일가 — 실제 시장 기준의 셋째 체결 자, 미국도 덮음) `[확인필요: 분봉 출처·이용 조건]`
- 슬리피지 가정에 호가 단위 하한·손익분기 슬리피지 참고 열(편도 0.10% 는 근거 없는 첫 값)
- 미국 다리의 실수령 기준(환전 스프레드·양도세 참고 칸, 달러 현금 칸)
- KIS 경로에 취소·매수가능금액 사전 조회·모름 주문 멈춤 리허설(자동 취소 **규칙**이 아니라 멈춤용 **능력** — 사용자 보류와 다르다)
- 쉬는 현금의 이자 참고 열 · 장중 감시의 계좌 수준 손익 기록

**검증·실전 전환**
- 등록한 모든 변형의 전진 원장 + 시도 등록부(계좌 없이 전 변형이 표본 밖 기록을 병렬로)
- 관문을 "알파 증거" 와 "운영 준비" 로 가르고 알파 지출·조기 접기 — 사용자 결정
- 판정 대기 원장 정리(행마다 지금 표본/문 표본·예상 도달일, 못 닿을 행은 닫기) + 전수 그림자(손절 집행 같은 미시구조 질문은 모든 신호의 가상 보유로 표본 확대)
- H 규칙 그대로의 무작위 쌍둥이 1,000개(선정만 남기는 정확 검정) · 가족 단위 유효 시도 수·부트스트랩 단계 검정
- 계좌·성분 사이 정보 빌리기(축소 추정)와 탈락 부검표
- 실전 파일럿을 "실행 품질 실험" 으로 떼어 병렬화 + 사용자 숫자 셋(실전 목표 금액·중단 손실 한도·받아들일 최소 실력) — 사용자 결정

**운영·데이터**
- 발주 임계 경로를 무거운 배치에서 떼기 + 실패한 날 "보호 매도만" 모드 — 큼, 사용자 결정
- 실전 키 격리(GitHub Environment)·자격 증명 만료 달력·설정 변경 이력 — 사용자 결정
- 읽기 한도: 발주 몫 예약·차단 순서(웹 → 주간·월간 → 리포트 → 발주)·월말 예측
- 소액 승인형 리허설(텔레그램 승인 버튼) + 웹·DB 밖 멈춤 스위치 — 사용자 결정
- 재해 복구: GitHub 밖 사본·원장 일일 백업·"새 DB 로 갈아타기" 훈련 — 사용자 결정(`BACKUP_KEY`)
- 감독 보고의 층(운영 신호등 한 줄·주간 예외 보고·결정 대기함)

## 3. 실전 주문을 열기 전에 반드시 있어야 하는데 지금 없는 것

6. 읽기 한도가 바닥나도 발주·보호 경로가 사는 예약 몫
