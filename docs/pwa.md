# 홈 화면 앱 (PWA)

> 2026-09-17 작성. 사용자 요청 "앱으로도 만들어줘" 에 대한 답이다.

---

## 0. 왜 네이티브 앱이 아닌가

앱스토어에 올리려면 **애플 개발자 계정이 연 99달러**이고 카드 등록이 필요하다.
CLAUDE.md 비용 규칙이 둘 다 금지한다(운영 비용 0원, 카드 등록 요구 서비스 금지).
구글 플레이도 최초 25달러가 든다.

설치형 웹앱(PWA)은 **0원**이고, 지금 있는 화면을 그대로 쓴다. 홈 화면에 아이콘이
생기고, 열면 주소창 없이 전체화면으로 뜬다. 사용자 한 명이 쓰는 앱에 필요한 것은
여기까지다.

| | 네이티브 | **PWA (고른 것)** |
|---|---|---|
| 비용 | 연 99달러 + 카드 | 0원 |
| 배포 | 심사 며칠 | 푸시하면 끝 |
| 아이콘·전체화면 | 됨 | 됨 |
| 코드 | 따로 만든다 | 지금 화면 그대로 |
| 잠금화면 알림 | 됨 | 텔레그램으로 이미 받고 있다 |

알림을 웹 푸시로 옮길 이유가 없다. 배치가 텔레그램으로 보내고, 그쪽이 폰이 꺼져
있어도 도착한다.

## 1. 설치 방법

| 기기 | 방법 |
|---|---|
| 아이폰 (사파리) | 공유 → **홈 화면에 추가** |
| 안드로이드 (크롬) | 메뉴 → **앱 설치** 또는 홈 화면에 추가 |

설치 전에 **로그인해 두어야 한다.** 설치된 앱은 같은 쿠키를 쓴다.

## 2. 무엇이 들어갔나

| 파일 | 무엇 |
|---|---|
| `web/app/manifest.ts` | 이름·아이콘·시작 화면(`/recommend`)·전체화면 선언 |
| `web/public/icon-*.png` | 아이콘. 외부 라이브러리 없이 zlib 로 직접 그렸다 |
| `web/public/sw.js` | 서비스 워커. 설치 조건을 채우고 오프라인 안내를 낸다 |
| `web/public/offline.html` | 연결이 끊겼을 때 보이는 안내 (하단 책임 고지 포함). **바꾸면 `sw.js` 의 `SHELL` 이름을 올린다** — 껍데기는 캐시 우선이다 (docs/infra.md 25.232) |
| `web/components/ServiceWorker.tsx` | 워커 등록 (실패해도 화면은 그대로 동작) |

시작 화면을 `/recommend` 로 둔 이유: 매일 여는 것이 오늘의 추천이다. 바로가기로
`내 포트폴리오`·`시스템 상태` 도 넣었다(길게 눌러 나오는 메뉴).

## 3. 데이터를 폰에 남기지 않는다

서비스 워커가 있으면 보통 응답을 캐시해 빠르게 만든다. **여기서는 하지 않는다.**

- `/api/*` 는 가로채지도 저장하지도 않는다. 시세·재무는 제3자 제공이 금지돼 있고
  (KRX 약관), 매매 기록은 사적인 값이다
- 로그인한 화면(HTML)도 저장하지 않는다. 캐시된 화면이 로그아웃 뒤에도 보이면
  "로그인 없이는 어떤 데이터도 반환하지 않는다" 는 절대 규칙이 깨진다
- 캐시하는 것은 아이콘과 오프라인 안내뿐이다

그래서 오프라인에서는 **옛 숫자 대신 "지금은 볼 수 없습니다"** 가 보인다.
옛 시세를 지금 값으로 착각하는 쪽이 더 위험하다.

설치용 정적 파일(매니페스트·아이콘·워커·안내)은 로그인 없이도 받을 수 있게
`proxy.ts` 가 통과시킨다. 데이터가 들어 있지 않고, 이것까지 막으면 브라우저가
매니페스트를 읽지 못해 설치가 실패한다.

## 3.1 메뉴는 폰에서 아래에 둔다 (2026-09-17 사용자 요청)

설치형 앱은 주소창이 사라져 **위쪽 메뉴가 화면 맨 끝에 붙는다.** 한 손으로 쥔 폰에서
엄지가 닿지 않는 자리다. 사용자가 "메뉴가 너무 위에있어" 라고 했다.

| 화면 폭 | 메뉴 |
|---|---|
| 폰 (640px 미만) | **아래 고정 막대** 다섯 칸 + 위에는 지금 화면 이름만 얇게 |
| 그보다 넓으면 | 지금까지대로 위쪽 가로 메뉴 일곱 |

- ~~아래 막대에는 자주 쓰는 다섯만 둔다(추천·적립·찾기·내 계좌·알림)~~ → 3.2 에서 바꿨다
- 노치·홈 인디케이터를 피해 `env(safe-area-inset-top/bottom)` 만큼 띄운다. 이것을
  빼면 설치형 앱에서 메뉴가 시계 밑으로 들어가거나 인디케이터에 가린다
- **`viewport-fit=cover` 는 쓰지 않는다.** 처음에는 넣었다가 뺐다. cover 는 레이아웃
  영역을 브라우저 툴바 뒤까지 넓혀서, `fixed bottom-0` 인 아래 메뉴가 사파리 하단
  툴바에 가려 보이지 않는다(2026-09-17 사용자 보고 "안보여"). 빼면 브라우저가 안전
  영역을 알아서 비워 준다. 배경이 노치 아래까지 이어지지 않는 대신 **메뉴가 보인다**
- 같은 이유로 iOS 상태표시줄은 `black-translucent` 가 아니라 `default` 다. translucent
  는 본문을 상태표시줄 아래까지 밀어 넣는다
- 배경은 반투명이 아니라 불투명이다. 뒤 글자가 비치면 메뉴가 없는 것처럼 보인다
- 본문에도 아래 여백(막대 높이 + 안전 영역)을 줘서 마지막 줄이 막대에 가리지 않게 한다

## 3.2 폰 화면 다듬기 (2026-09-18 사용자 요청, 5단계 중 1단계)

사용자: "핸드폰으로 보는 웹앱 UI 가 조금 불편한데" → 고른 것: **메뉴·조회 단추가 부자연스럽고 메뉴·단추를
찾기 어렵다 · 표가 옆으로 넘친다 · 화면이 너무 길다 · 누르기 불편하다** (글씨 크기는 고르지 않았다).
폰 폭으로 띄워 보니 이랬다.

| 불편 | 본 것 |
|---|---|
| 메뉴를 찾기 어렵다 | 아래 막대가 **아이콘 없는 글자 여섯 칸**. 리포트·백테스트·시스템 상태는 **긴 화면 맨 아래 고지 옆**. 종목 상세에 **뒤로가 없다**(설치형 앱은 브라우저 뒤로도 없다) |
| 화면이 길다 | 제목이 **두 번**(위 제목줄 + 본문). 화면마다 docs 파일 경로가 든 설명 문단 |
| 누르기 불편하다 | 국내/미국 탭·돋보기·로그아웃이 손가락보다 작다 |

**1단계에서 바꾼 것 — 공통 뼈대**

- 아래 막대: **추천·적립·찾기·내 계좌·분석·더보기** 여섯 칸(2026-10-08 사용자 지시로 알림 자리에 종목 분석, 알림은 더보기로 — infra 25.1017), **아이콘 + 글자**, 높이 3.5rem(`--phone-nav`)
  (사용자 결정. 구성은 `web/lib/menu.ts` 한 곳). 처음에는 적립을 더보기로 보낸 다섯 칸이었는데, 같은 날
  사용자가 "장기 적립은 메뉴에 노출" 을 원해 여섯 칸으로 했다. 한 칸 약 62px(375px 폭)
- **더보기**(`/more`): 일일 리포트·백테스트·시스템 상태·설정과 로그아웃. 이 화면들에 있으면 더보기 칸이 켜진다
- 위쪽 제목줄: **뒤로 단추**(아래 막대에 없는 화면 — 종목 상세·더보기 안의 화면), 화면 이름, 검색.
  뒤로는 들어온 길이 있으면 그리로, 없으면(알림에서 바로 연 경우) 정해 둔 곳으로 간다(`BACK_TO`)
- 로그아웃은 제목줄에서 더보기로 옮겼다 — 거의 안 쓰는 것이 매 화면 제목줄을 차지했다
- 본문 제목은 **폰에서 숨긴다**(제목줄과 중복). 설명은 폰에서 "ⓘ 이 화면은" 을 눌러야 펼친다(`PageHeader`).
  규칙 문서 경로는 넓은 화면에만 "규칙: docs/…" 로 적는다 — 폰에서는 열 수도 없는 경로가 자리만 차지했다
- 누르는 것은 손가락 크기(44px, Apple 권고)로: 아래 막대 칸, 뒤로·검색 단추, 국내/미국 탭(폰에서 폭을 반씩 나눈다)
- 넓은 화면은 그대로다(위쪽 가로 메뉴, 본문 제목·설명)

**2단계 — 종목 찾기** (2026-09-18)

- 전: [조회] 가 조건 목록 **한가운데 떠서** 입력칸을 가렸다(폰 아래 메뉴 위에 붙는 sticky). 결과는 열 11개짜리 표라 옆으로 밀어야 했다
- **자주 쓰는 조건**(프리셋·저장한 조건)을 맨 위에. 누르면 바로 찾는다(원래도 그랬다)
- 세부 조건은 **"조건 바꾸기" 칸으로 접는다.** 폰에서는 처음에 접혀 있다 — 처음 열 때 기본 조건으로 이미 찾으므로
  결과가 먼저 보인다. 넓은 화면은 처음부터 펼친다
- [조회] 는 **조건 칸의 끝**에 붙는다(폰에서 떠 있지 않다). 누르면 칸을 접고 결과로 내려간다. 넓은 화면은 전처럼 아래에 붙는다
- 결과: 폰은 **종목 카드**(열 이름·값 3줄 격자, 정렬 기준 값은 굵게), 넓은 화면은 표. **둘이 같은 열 정의**(`resultColumns`)를 쓴다
- 입력칸·고르기·단추는 폰에서 44px. CSV 내보내기는 넓은 화면에만(폰에서 파일을 받아 쓸 일이 없다)

**3단계 — 종목 상세** (2026-09-18)

- 전: 카드 열 개(빈 것 포함)가 세로로 쌓이고, 성과(여덟 칸)·5년 재무·분기(여덟 분기)·배당·근거표가 옆으로 넘쳤다
- **구역 바로가기**(폰, 제목줄 아래 붙는 줄): 가격·신호·성과·재무·뉴스·일정. 카드마다 `id` 가 있고 테스트가 짝을 본다
- **데이터 없는 구역은 한 줄**(제목 + "데이터 없음 — 사유")
- 재무 셋(5년·분기·배당)을 붙여 두었다 — 뉴스가 사이에 끼어 있었다. 넓은 화면도 같은 순서다
- 표: 성과는 **지표를 행·기간을 열**로 뒤집어 폭에 들어가게. 5년 재무는 폰에서 **최근 3년**, 분기는 **최근 4개**
  (열 이름도 "2026 2분기" 까지만). 배당은 보고서 연도·배당성향 기준 글자를 폰에서 뺀다
- **근거표**(`CriteriaTable`, 추천·장기 적립도 같이 쓴다): 폰에서는 기준마다 두 줄 — 판정·기준·기준일 / 값·문턱·출처.
  넓은 화면은 표. 같은 행을 그리고, 오래된 기준일 노란 표시도 같다
- 누르는 것: 관심 등록, 기간(3M·1Y·3Y·5Y), 신호 기간 단추, 뉴스 줄을 폰에서 키웠다
- 화면 글의 docs 경로를 뺐다(근거표의 "문턱을 정의하는 문서" 는 근거표 설계라 남긴다)

**4단계 — 포트폴리오·알림** (2026-09-18)

- 전: 매매 입력은 "[매매 기록] 탭에서 넣으라" 는 문장뿐이었고, 하위 탭 다섯이 옆으로 넘쳐 "복기" 가 잘렸다.
  복기 집계는 아홉 칸 표, 근거·지우기·읽음·빼기 같은 단추는 손가락보다 작았다
- 포트폴리오 맨 위에 **[＋ 매매 입력]** — 기록 탭으로 가서 입력 칸으로 내려간다
- 하위 탭: 폰에서 **한 줄 다섯 칸**(보유·기록·배당·손익·복기 + 건수). 넓은 화면은 전처럼 알약에 긴 이름
- 복기 집계: 폰은 집단마다 카드, 넓은 화면은 표
- 입력칸 44px, 저장 단추는 폰에서 폭 전체, 줄 안의 작은 단추는 누를 자리를 넓혔다
- 알림: 탭 두 칸(폰에서 반씩), 고르기·체크·모두 읽음·읽음·빼기를 손가락 크기로. 관심 종목 추가 단추는 폰에서 폭 전체
- (보유 목록은 원래 카드였다)

**5단계 — 나머지 화면** (2026-09-18)

- 여러 칸 표를 폰에서 카드로: 백테스트 전략 비교(열 칸)·스트레스(다섯 칸), 시스템 상태 무응답 감시(여섯 칸). 넓은 화면은 표
- 누르는 것을 손가락 크기로: 추천·장기 적립의 기간/보기 탭, 새로고침, 관심 등록·종목 상세, 위성 ETF 묶음, 백테스트 입력·실행, 상태의 수동 실행
- 화면 글의 docs 경로를 뺐다(추천 성적표·적립 종목·백테스트·상태). 근거표의 문턱 문서는 남긴다
- 종목 상세 바로가기 칩 여백을 줄여 여섯이 390px 에 한 줄로 들어가게 했다(운영 확인에서 "일정" 이 잘렸다)
- 설정·일일 리포트는 이미 폰에 맞았다(큰 입력칸, 아래에 붙는 저장, 표 없음). 그대로 둔다

**운영 확인**: 1단계 → 83f743c, 2~4단계 → 036cb7f 배포(2·3단계 푸시는 Vercel 하루 한도로 거절됐다가 4단계와 함께 올라갔다, infra 25.15).
운영 폰 흉내로 종목 찾기 결과 카드·종목 상세 바로가기·빈 구역 한 줄을 실제 데이터로 봤다.

**남은 것**: 실제 폰에서 사용자가 써 보고 어색한 곳을 말해 주면 고친다. D1 에 재무·성과가 차면(9/19~) 표 안의 숫자가 들어간 모습도 다시 본다.

### 3.3 폰 화면을 확인하는 방법

**로컬(데이터 없이 틀만)**: 앱 안 브라우저로 `stock-manager` 미리보기(포트 4310)를 띄우고 모바일 크기(375×812)로 본다.
로그인은 **로컬 전용 임시 비밀키**로 한다 — `web/.env.development.local`(저장소에 안 올라간다, `.env.*`)에
임시 `AUTH_SECRET` 을 두고, 같은 키로 `lib/auth.createSessionToken()` 을 불러 만든 값을 `sm_session` 쿠키로 넣는다.
실제 비밀번호·비밀키는 쓰지 않는다. 로컬 웹이 연결된 DB 가 막혀 있으면 빨간 띠가 뜨는 것은 정상이다.
확인이 끝나면 `.env.development.local` 을 지운다(남으면 나중의 로컬 설정보다 앞선다).

**운영(실제 데이터)**: 사용자 크롬(로그인된 창)에서 화면을 연 뒤, 스타일시트의 `min-width`/`width >=` 미디어 규칙을
지우고 본문을 폭 390px 상자에 옮기면 폰 배치가 거의 그대로 보인다. 사이트가 `X-Frame-Options: DENY` 라 iframe 으로는
띄울 수 없다(클릭재킹 방지라 그대로 둔다). 창이 최대화돼 있으면 창 크기 바꾸기는 먹지 않는다.

## 4. 한계

- 아이폰은 **설치된 PWA 에서만** 웹 푸시를 지원한다(iOS 16.4+). 지금은 쓰지 않는다
- 오프라인에서 지난 리포트를 볼 수 없다. 3장의 결정에 따른 것이다
- 앱 이름·아이콘을 바꾸면 사용자가 **다시 설치**해야 반영되는 경우가 있다
- 안드로이드에서 "앱 설치" 가 뜨려면 서비스 워커가 fetch 를 다뤄야 한다. 그래서
  아무것도 캐시하지 않더라도 워커를 둔다
