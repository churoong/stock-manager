## 다음에 볼 큰 일 (2026-09-28, 스케줄·교차검증에서)

- **백테스트 워밍업을 채우려면 백필을 더 앞에서** (25.532·25.537): 5년 실행은 시작일보다 900일 앞(약 2019-04)부터 가격이 있어야 모멘텀·리스크가 첫 달부터 난다. 국내 백필 기본 시작은 2021-09-01, 미국은 1,300일. 쓰기 예산(Turso 월 1천만 행) 안에서 나눠 해야 해 Actions 가 돌아온 뒤의 일이다. 그 전까지 저장된 백테스트 결과는 종합·모멘텀·리스크 초반이 현금이다

## 3. 이번 세션(2026-09-17 밤, 클라우드)에 한 일

### 3.1 종목 선택 엔진 강화 A~D — 사용자 승인 작업

사용자 요청: *"종목 선택에 대한 로직을 강화하자. 분명한 건 전제로 입력했던 사실 그대로 데이터야.
지금 구현한 지표들 외에 최근 트렌드나 획기적인 지표들을 추가해야 더 진보한 엔진이 될 거 같아."*

전제는 그대로다 — **DB 에 있는 실제 수치만, 문서 없는 팩터는 구현하지 않는다, 계산은 파이썬에서,
적재와 백테스트가 같은 함수를 부른다.** 무료로 얻을 수 있는 "최신 트렌드" 데이터가 거의 없어
(구글 트렌드 공식 API 없음, 소셜·애널리스트 추정치 유료) **학계에서 검증됐는데 이 엔진에 없던 지표**로 갔다.

| 묶음 | 상태 | 문서 |
|---|---|---|
| **A. 가격·거래량 4개** | 완료 | `docs/factors.md` 10.1 |
| **B. 재무제표 3개** | 완료 | `docs/factors.md` 10.2 |
| **C. 지수 추세 필터** | 완료 | `docs/signals.md` 3.5 · `docs/backtest.md` 2.4 |
| **D. 내부자 매매** | **국내 완료** (2026-09-18 실측 뒤 수집기까지). 미국 Form 4 는 아직 | `docs/signals.md` 8장 · `docs/data-sources.md` 16절 |

**A — 무엇을 왜**
- 52주 고점 근접도(George & Hwang 2004) · 모멘텀 꾸준함(Da, Gurun & Warachka 2014) ·
  변동성 조정 모멘텀(Barroso & Santa-Clara 2015) → **모멘텀** 3→6 지표
- Amihud 비유동성(2002) → **리스크**(낮을수록 좋음) 7→8 지표
- 창의 정의는 하나다: 형성 창 = 종가 계열 끝에서 21일 뺀 지점부터 뒤로 253개(12-1 모멘텀과 같은 창).
  52주 = 252일, Amihud = 최근 63일·30일 이상
- 적재 `scores.load_series()` 가 최근 274 거래일 계열을 **한 질의**로 읽는다(약 25만 행).
  거래대금은 `prices.value` 우선, 없으면 원 종가×거래량
- 백테스트 `PriceView(prices, cutoff, turnover)` + `values()`. **적재와 백테스트가 같은
  `scoring.price_series_metrics` 를 부른다** — 두 곳 계산이 어긋나면 백테스트가 의미를 잃는다
- `momentum_vol_adjusted` 는 연환산 변동성이 `VOL_ANN_EPS`(1e-6) 이하면 None.
  매일 같은 비율로 오른 급수는 부동소수 오차로 분산이 1e-30 쯤 남아 1e14 가 튀었다(테스트가 잡았다)

**B — 무엇을 왜**
- 자산 성장률(Cooper, Gulen & Schill 2008) · 유동비율 · 피오트로스키 축소판 6항목 → **퀄리티** 5→8 지표
- 자산 성장률은 **퀄리티에 방향 −**. 성장 팩터(+)에 넣으면 평균에서 서로 지운다
- 피오트로스키는 원본 9개 중 컬럼으로 낼 수 있는 6개. 매출총이익률→영업이익률, 장기차입금→비유동부채
  (두 해 다 없으면 부채총계, **두 해는 반드시 같은 잣대**). **하나라도 판정 불가면 전체 NULL** —
  부분 합은 "모름" 을 "나쁨" 으로 읽는다
- `CALC_VERSION` 1 → **3** (A 에서 2, B 에서 3). 옛 점수 행과 섞이지 않는다

**C — 무엇을 왜**
- Faber(2007) 규칙: 지수 종가 < **200 거래일** SMA 면 약세 → 신규 매수 **권장 비중 × 0.5**(설정)
- **점수·신호·플래그는 바꾸지 않는다.** 사이징에만 곱한다. 근거표에 "시장 국면" 행(지수·200일선·배수·출처·날짜)
- 원본은 약세면 전량 현금이지만 여기서는 비중만 줄인다 — 규칙이 틀렸을 때의 손해를 반으로
- 지수가 200일치 미만이거나 7일 넘게 오래되면 **미판정 → 배수 1.0**(모르는 것을 위험하다고 단정하지 않는다)
- 새 표 `index_prices`(0028), 수집은 yfinance `^KS11` `^KQ11` `^GSPC` 한 번에(하루 3행)
- 백테스트 엔진이 **현금을 표현**하게 바뀌었다(비중 합 < 1 이면 나머지 현금). 살 수 없는 종목의 몫은
  남은 종목에 나눠 **이전 결과는 그대로**다. `--trend-filter` 로 켠다
- 배수 0.5 는 추정 `[확인필요]` — 켠/끈 백테스트를 비교해 정한다

**D — 어디까지, 그리고 이어가는 법**
- 이 세션은 `opendart.fss.or.kr` 과 `sec.gov` 가 **네트워크에서 막혀** 스펙을 실측하지 못했다.
  추측으로 수집기를 쓰지 않았다(CLAUDE.md "잘 모르는 외부 API 스펙은 추측하지 말고 [확인필요]")
- 만든 것: 표 `insider_trades`(0029) · `services/insider.py`(최근 90일 순매수, **접수일 ≤ 기준일**) ·
  신호 근거표의 **참고 행**(`passed=null`, 팩터 아님) · probe 스크립트와 워크플로
- 팩터에 안 넣은 이유: 보고가 회사당 몇 건이라 분포가 성기다. z-score 를 내면 몇 건이 순위를 휘두른다
