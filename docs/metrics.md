# 성과 지표 계산식

- 기준: `CLAUDE.md` 의 스코어링 항목
- 모든 지표는 **일간 수익률**로 계산하고 **연환산 계수 252**를 쓴다
- 순수 함수로 구현한다. 데이터베이스를 모르고, 같은 입력에 항상 같은 값을 낸다
- **값을 만들어 내지 않는다.** 표본이 모자라면 `None` 을 돌려준다

여기 적힌 것만 구현한다. 문서에 없는 지표는 만들지 않는다.

---

## 0. 공통 규칙

### 일간 수익률

```
r_t = P_t / P_{t-1} - 1
```

수정주가가 있으면 수정주가를 쓴다. 액면분할과 배당락에서 가짜 폭락이 잡히지 않게 하기 위해서다. 없으면 종가를 쓴다 — **단, 수정주가 계열의
가운데(앞뒤로 수정주가가 있는 자리)에 빈 행은 원 종가를 그대로 쓰지 않는다**. 원 종가 한 행이 분할 전 수정 계열에 끼면 가짜 폭락이 된다.
25.701 은 그런 행을 뺐고, 국내 `adjust_kr` 가 누적 계수 1 인 날을 정상적으로 비워 두는 것까지 빼게 되어 25.715·25.719 에서 이렇게 바꿨다:
앞뒤 수정 계수가 같으면 직전 계수로 옮기고(구멍), 다르면 원 종가와 옮긴 값 가운데 직전 값에 더 가까운 쪽. 옮긴 종목 수는 배치 경고로 남긴다.
앞뒤 끝의 빈 행(조정 전 구간·아직 조정 안 된 최근)은 원 종가다. **이 규칙의 정의처는 `services/adjust.fill_adjusted` 이고 성과 지표·백테스트
가격·점수 계열(모멘텀·리스크)이 같이 쓴다** (2026-10-10, docs/infra.md 25.1101 — 백테스트와 점수 계열은 `COALESCE(adj_close, close)` 로
읽어 같은 구멍에 원 종가가 들어갔다).

가격이 0 이하이면 그 구간의 수익률은 계산하지 않는다. 거래정지 종목에서 0 이 들어오는 경우가 있다.

**0 이하 종가는 값이 없는 날이다** (2026-09-26, docs/infra.md 25.203). 수익률만이 아니라 **CAGR·MDD 도** 그날을 뺀 계열로 낸다(`metrics.compute` 가 처음에 한 번 뺀다). 예전에는 가격 경로를 그대로 봐서 꾸준히 오른 종목이 0 하루로 MDD −100% 가 됐다. 적재(`db.bulk_upsert_prices`)도 그런 행을 넣지 않는다.

**두 행이 11일(`MAX_SESSION_GAP_DAYS`)보다 벌어져 있으면 그 수익률은 버린다** (2026-09-22 추가).

`P_t / P_{t-1} - 1` 이 **하루치**라는 것은 두 행이 잇닿은 거래일일 때만 참이다. 2주 쉬었다
재개한 종목의 첫날 움직임은 그동안 쌓인 것이라 하루치가 아니다. 그것을 일간 수익률로 세면
변동성·샤프·소르티노가 그 한 점에 끌려가고, **정지 이력이 있는 종목이 일제히 "위험한 종목"**
으로 보인다.

11 이라는 숫자는 **실측**이다. `exchange_calendars` 로 2016~2026 의 거래일 사이 간격을 재면
XKRX 최장 **11일**(2017-09-29 → 10-10, 추석 + 임시공휴일 + 개천절), XNYS 최장 4일이다.
그러므로 **정상 휴장은 절대 안 걸린다** — 걸리는 것은 거래정지나 수집 구멍뿐이다.

- **버린다. 환산하지 않는다.** 며칠치인지 알더라도 루트로 나눠 하루치로 바꾸는 것은
  그 기간에 매일 같은 크기로 움직였다는 가정이라, **없는 정보를 만드는 일**이다
- **CAGR 과 MDD 는 이 규칙과 무관하다.** 둘은 수익률이 아니라 **가격 경로**에서 나온다.
  쉬는 동안 값이 떨어졌다면 그것은 실제 낙폭이므로 MDD 에 들어가는 것이 맞다
- **알고 두는 한계.** 사흘짜리 짧은 정지는 긴 연휴와 구별되지 않아 못 잡는다. 구별하려면
  그 시장의 거래일 목록이 필요한데 계산 함수는 DB 도 달력도 모른다
  `[확인필요: 거래일 목록을 넘기는 편이 나은지]`

### 연환산 계수

**252** 를 쓴다. 한국과 미국 모두 연간 거래일이 대략 이 수준이다. 252 와 250 의 차이는 변동성에서 0.4% 수준이라 실무상 무시할 수 있다.

### 표본 하한

| 기간 | 최소 거래일 |
|---|---|
| 1년 | 200 |
| 3년 | 600 |
| 5년 | 1000 |

**창의 시작과 끝도 채워야 한다** (2026-09-29, calc_version 3, docs/infra.md 25.703). 첫 시세가 창 시작일 뒤 **45일** 안에 있고, 마지막 시세가
기준일 전 11일(거래일 간격 상한) 안에 있어야 값을 낸다. 행 수만 보면 상장 2.3년 종목의 "3년" 값이나, 마지막 6개월이 빈 계열의 "기준일 현재" 값이
나온다. 못 맞추면 개수만 남기고 값은 `None` — 점수는 더 짧은 창을 고른다.

**하한에 못 미치면 그 지표는 `None` 이다.** 100일치로 계산한 값을 "1년 변동성" 이라고 부르면 안 된다. 상장 직후 종목이나 거래정지 기간이 긴 종목이 여기 걸린다.

### 무위험수익률

연율로 받아 **연율 그대로** 뺀다 — 샤프·소르티노 모두 `(CAGR - rf_annual) / 연환산 편차` 라 일간으로 바꾸지 않는다.
(예전 문서에 적힌 `rf_daily = (1 + rf_annual)^(1/252) - 1` 기하 환산은 어떤 코드도 쓰지 않았다 — docs/infra.md 25.684 에서 지웠다.)

**지금 값 하나를 과거 창 전체에 쓴다.** 설정 `risk_free_manual` 의 현재 값이다. 3년 창 안에서 금리가 바뀌었어도, 백테스트의
과거 리밸런스 시점에도 같은 값이다. 샤프는 `rf ÷ σ` 가 종목마다 달라 금리 수준이 **순위를 바꿀 수 있다**(저금리 시점의
백테스트 순위가 오늘 금리로 뒤집힐 수 있다). 날짜가 붙은 금리 이력을 두기 전까지의 알려진 한계다 (25.684, 감사)

값이 없으면 0 으로 두지 않고 **샤프와 소르티노를 `None` 으로 만든다.** 0 으로 두면 무위험수익률이 0인 세상의 값이 나오는데, 그게 맞는 값처럼 보인다.

## 1. CAGR (연평균 성장률)

```
CAGR = (P_end / P_start)^(1 / 연수) - 1

연수 = (마지막 날 - 첫날) / 365.25
```

`CLAUDE.md` 의 정의를 그대로 따른다.

**연수는 달력 기준이다.** 거래일이 아니다. 3년 창이라도 실제 데이터가 2.8년이면 2.8을 쓴다. 거래일로 나누면 휴장이 많은 해에 값이 부풀려진다.

- 시작 가격이 0 이하이면 `None`
- 연수가 0 이면 `None`
- 기간이 1년 미만이어도 계산한다. 다만 연환산된 값이라 과대·과소 해석에 주의한다

**배당은 나라마다 다르다** (2026-09-26 정정, docs/infra.md 25.244). 계열은 `COALESCE(adj_close, close)` 다. **국내**는 수정주가가 분할만 조정하므로(docs/adjust.md) **가격 수익**이고, **미국**은 야후 수정종가(Adj Close)라 **배당 재투자 포함 총수익**이다. 예전 이 문단은 "배당은 넣지 않는다" 였는데 미국에는 사실이 아니었다. 두 나라의 CAGR·샤프를 바로 견주지 않는다 — 한국·미국은 원래 같은 잣대로 비교하지 않는다(CLAUDE.md 스코어링). 백테스트 결과는 나라에 맞는 문구를 붙인다.

## 2. MDD (최대 낙폭)

```
running_max_t = max(P_1 ... P_t)
drawdown_t = P_t / running_max_t - 1
MDD = min(drawdown_t)
```

**음수로 돌려준다.** 35% 하락은 `-0.35` 다. 리스크 팩터는 이 값의 **절댓값**을 "클수록 나쁘다" 로 쓴다 (`scoring.py`, 25.684 정정).

함께 돌려주는 값이 셋 더 있다.

| 값 | 뜻 |
|---|---|
| `mdd_peak_date` | 낙폭이 시작된 고점의 날짜 |
| `mdd_trough_date` | 바닥 날짜 |
| `mdd_recovery_days` | 바닥에서 고점을 회복하기까지 걸린 **관측 행 수**(저장된 시세 행 — 거래정지로 행이 없는 날과 종가 0 인 날은 세지 않는다). 아직 회복 못 했으면 `None`. 정지 이력이 있으면 실제 거래일보다 **짧게** 나온다 — 이 모듈은 거래일 달력을 모른다 (2026-09-27 바로잡음, docs/infra.md 25.305) |

**한 번도 고점 아래로 내려가지 않았으면 MDD 0, 회복 기간 0 이다** (2026-09-27, docs/infra.md 25.310).

**회복 기간이 `None` 인 것과 0 인 것은 다르다.** `None` 은 아직 회복하지 못했다는 뜻이고, 이것이 오히려 더 나쁜 신호다. 화면에서 "미회복" 으로 표시한다.

## 3. 연환산 변동성

```
σ_daily = stdev(r, 표본표준편차)     # ddof = 1
σ_annual = σ_daily × √252
```

**표본표준편차를 쓴다.** 모집단 표준편차가 아니다. 우리가 가진 것은 전체가 아니라 표본이다. 관측치가 2개 미만이면 `None`.

---

## 4. 샤프지수

```
샤프 = (CAGR - rf_annual) / σ_annual
```

`CLAUDE.md` 의 정의를 그대로 따른다.

**분자에 CAGR 을 쓴다.** 산술평균의 연환산이 아니다. 두 방식이 널리 쓰이는데, 기준 문서가 CAGR 을 따로 정의해 두었으므로 그것과 맞춘다. 변동성이 큰 종목에서 산술평균 방식보다 값이 낮게 나온다. 이쪽이 실제 투자 성과에 가깝다.

- σ_annual 이 0 이면 `None`. 움직이지 않은 종목의 샤프는 뜻이 없다
- rf 가 없으면 `None`

---

## 5. 소르티노지수

```
하방편차_daily = √( Σ min(r_t, 0)² / (n - 1) )
하방편차_annual = 하방편차_daily × √252

소르티노 = (CAGR - rf_annual) / 하방편차_annual
```

**기준점은 0 이다.** 무위험수익률이 아니다. "손실이 난 날" 만 위험으로 본다는 뜻이고, 이 정의가 가장 널리 쓰인다.

**제곱합을 나누는 수는 `n - 1` 이다 (n = 전체 관측치 수).** 하락한 날의 개수가 아니다. 하락한 날로 나누면 하락이 드문 종목의 하방편차가 과대평가되어 소르티노가 낮아진다.

- 하방편차가 0 이면 `None`. 한 번도 하락하지 않은 종목이다

## 6. 베타

```
베타 = Cov(r_종목, r_시장) / Var(r_시장)
```

- 표본 공분산과 표본분산을 쓴다 (ddof = 1)
- **같은 날짜끼리 맞춰서 계산한다.** 종목과 시장의 거래일이 다르면 겹치는 날만 쓴다. 이걸 안 맞추면 값이 통째로 틀린다
- **수익률도 짝으로 낸다** (2026-09-26, docs/infra.md 25.202). 날짜를 맞춘 뒤 한 쌍씩 보고, 어느 쪽이든 종가가 0 이하이거나 11일 넘게 벌어졌으면 **그 쌍을 양쪽에서 함께** 버린다. 양쪽 수익률을 따로 내고 뒤에서 자르면 한쪽에만 있는 빈 날 뒤의 짝이 전부 어긋난다 (`metrics.paired_returns`)
- 겹치는 날이 표본 하한에 못 미치면 `None`
- 시장 분산이 0 이면 `None`

**벤치마크는 시장별로 다르다.** 국내는 KOSPI, 미국은 S&P 500 이다. 한국 종목의 베타를 S&P 500 으로 재면 뜻이 달라진다.

---

## 7. 계산하지 않는 것

아래는 요구되지 않았으므로 만들지 않는다. 필요해지면 이 문서에 먼저 적는다.

- 정보비율, 트레이너지수, 칼마지수
- 알파
- 롤링 지표
- 배당 재투자 기준 총수익을 **따로** 내는 것 — 미국 계열은 야후 수정종가라 이미 총수익이다(1장). 국내 총수익을 따로 만들지 않는다는 뜻이다

## 8. 저장

`performance_metrics` 표에 기간별로 한 행씩 쌓는다.

| 열 | 비고 |
|---|---|
| `window` | `1Y` `3Y` `5Y` |
| `data_points` | 계산에 쓴 거래일 수. 하한 미달 여부를 나중에 확인할 수 있다 |
| `risk_free_rate_used` | 그때 쓴 무위험수익률. 나중에 값이 바뀌어도 재현된다 |
| `benchmark` | 베타 계산에 쓴 지수. 베타가 `None` 이면 비운다 (25.684) |
| `calc_version` | 계산식이 바뀌면 올린다. 과거 값과 섞이지 않게 한다 |

**계산식을 바꾸면 `calc_version` 을 올리고 새 행을 쌓는다.** 과거 행을 덮어쓰지 않는다. 어떤 식으로 계산한 값인지 나중에 알 수 있어야 한다.
